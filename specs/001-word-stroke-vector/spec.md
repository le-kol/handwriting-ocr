# Feature Specification: Векторизация штрихов слова

**Feature Branch**: `001-word-stroke-vector`

**Created**: 2026-08-11

**Status**: Draft

**Input**: User description: "Добавить функционал получения векторного представления слова из его изображения на скане. Конечная цель — использование вектора в будущем для генерации почерка из текста (offline handwriting synthesis). Данные о порядке и направлении написания штрихов недоступны (offline-скан) и на данном этапе не требуются — задача ограничивается геометрическим представлением формы штрихов слова кубическими кривыми Безье. Вход — существующая запись Word (Id, ScanId, четыре вершины рамки). Хранение — новая nullable-колонка curve_points в таблице words (real[] как трёхмерный массив), без отдельной таблицы; схема — через Liquibase."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Векторизация слова по запросу (Priority: P1)

Оператор (или вызывающая система) запрашивает векторизацию уже распознанного слова по его идентификатору. Система находит слово, извлекает выровненный фрагмент изображения скана по рамке слова (с учётом возможного поворота четырёхугольника и настраиваемого отступа), преобразует видимые штрихи в набор кубических кривых Безье и сохраняет результат непосредственно у этой записи слова. После успеха у слова появляется сохранённое геометрическое представление формы штрихов.

**Why this priority**: Это основной результат фичи и единственный путь получения данных, нужных для будущей генерации почерка.

**Independent Test**: На существующем скане с хотя бы одним словом с валидной рамкой запросить векторизацию по Id слова; убедиться, что представление сохранено у этой записи и доступно для последующего чтения.

**Acceptance Scenarios**:

1. **Given** существует слово с валидной рамкой и доступным файлом скана, **When** запрошена векторизация этого слова, **Then** система сохраняет у записи слова набор кубических кривых Безье (каждая кривая — 4 контрольные точки с координатами x, y) и подтверждает успешное завершение.
2. **Given** рамка слова повёрнута (не выровнена по осям), **When** запрошена векторизация, **Then** фрагмент извлекается с выравниванием поворота рамки, а не как простой axis-aligned прямоугольник без учёта ориентации.
3. **Given** в конфигурации задан ненулевой отступ от границ рамки, **When** запрошена векторизация, **Then** извлекаемый фрагмент включает область с этим отступом вокруг рамки слова.
4. **Given** успешная векторизация завершена, **When** запись слова просматривается снова, **Then** сохранённое векторное представление присутствует у этой же записи (привязка только через Id слова, без отдельной сущности хранения).

---

### User Story 2 - Повторная векторизация уже обработанного слова (Priority: P2)

Оператор повторно запрашивает векторизацию слова, у которого представление уже было сохранено ранее (например, после смены параметров или улучшения качества скана). Система заново выполняет извлечение и аппроксимацию и заменяет прежнее представление новым.

**Why this priority**: Позволяет корректировать результат без ручной очистки данных; не блокирует MVP, но ожидаемо при настройке параметров.

**Independent Test**: Векторизовать слово дважды подряд; убедиться, что второе успешное выполнение обновляет сохранённое представление, а не создаёт вторую «запись вектора».

**Acceptance Scenarios**:

1. **Given** у слова уже есть сохранённое векторное представление, **When** повторно запрошена векторизация и она успешна, **Then** прежнее представление заменяется новым, и у слова по-прежнему одно актуальное представление.
2. **Given** у слова уже есть сохранённое представление, **When** повторная векторизация завершается ошибкой (файл недоступен или штрихи не выделены), **Then** ранее сохранённое представление не затирается частичным/пустым результатом.

---

### User Story 3 - Предсказуемые ошибки без порчи данных (Priority: P1)

При невозможности выполнить векторизацию система сообщает об ошибке понятным текстом и не оставляет частичного/пустого векторного представления у слова.

**Why this priority**: Целостность данных слова критична; частичные записи сделали бы последующую генерацию почерка ненадёжной.

**Independent Test**: Запросить векторизацию для несуществующего Id, для слова со сломанным/отсутствующим файлом скана и для фрагмента без читаемых штрихов; проверить коды/сообщения ошибок и отсутствие записи вектора в этих случаях.

**Acceptance Scenarios**:

1. **Given** слова с указанным Id не существует, **When** запрошена векторизация, **Then** система возвращает ошибку «не найдено» (404) с текстовым сообщением, без изменений в данных.
2. **Given** слово найдено, но файл скана отсутствует или повреждён, **When** запрошена векторизация, **Then** система возвращает ошибку по карте ошибок проекта, не сохраняя векторное представление.
3. **Given** фрагмент слова извлечён, но из него нельзя выделить ни одного штриха, **When** векторизация завершается, **Then** система возвращает ошибку и не сохраняет пустое/частичное представление.

---

### Edge Cases

- Исходная рамка слова (X1..Y4 без отступа) не пересекается с изображением скана или площадь пересечения < 1 px²: ошибка (несоответствие рамки файлу), без сохранения вектора. Сообщение отлично от «вырожденной рамки».
- Рамка слова частично выходит за край скана: отступ применяется и клипается по границам изображения; уменьшение отступа с одной стороны у края — норма, не ошибка. Итоговый размер фрагмента после клипа отдельно не бракуется.
- Отступ или погрешность аппроксимации заданы некорректно в конфигурации (отрицательные/недопустимые значения): система не выполняет векторизацию и сообщает об ошибке конфигурации/входа согласно карте ошибок проекта.
- Слово существует, но координаты рамки вырождены (площадь < 1 px² или сторона < 1 px — см. research): система возвращает ошибку и не сохраняет вектор.
- Повторный OCR скана, заменяющий набор слов: новые слова не наследуют векторы старых записей (вектор живёт только у конкретной записи Word по Id); поведение удаления/замены слов скана не меняется этой фичей.
- Порядок и направление отдельных кривых в сохранённом наборе не нормируются и не интерпретируются на этом этапе.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система MUST принимать запрос на векторизацию существующего слова в контексте скана: идентификатор скана и идентификатор слова в маршруте (как у прочих операций со словами). Слово MUST принадлежать указанному скану.
- **FR-002**: Система MUST по четырём вершинам рамки слова (X1..Y4 в порядке, возвращаемом распознаванием) извлечь выровненный с учётом поворота фрагмент изображения скана, к которому принадлежит слово (ScanId).
- **FR-003**: Система MUST поддерживать настраиваемый отступ от границ рамки слова при извлечении фрагмента; значение отступа MUST быть конфигурируемым, не захардкоженным.
- **FR-004**: Если слово с указанным Id не найдено (в том числе не принадлежит указанному скану), система MUST вернуть ошибку 404 с текстовым телом сообщения (карта ошибок проекта, принцип III конституции).
- **FR-005**: Если исходный файл скана недоступен или повреждён, система MUST вернуть ошибку по карте ошибок проекта (см. Assumptions: 404 / 400) и MUST NOT сохранять векторное представление для этого слова.
- **FR-006**: Система MUST преобразовать изображение фрагмента слова в набор кубических кривых Безье, аппроксимирующих осевые линии (форму) штрихов слова; каждая кривая MUST задаваться ровно четырьмя контрольными точками (x, y).
- **FR-007**: Погрешность аппроксимации MUST быть конфигурируемой, не захардкоженной.
- **FR-008**: Порядок и направление между отдельными кривыми/сегментами MUST NOT требоваться и MUST NOT считаться частью контракта результата на данном этапе.
- **FR-009**: Если из фрагмента не удаётся выделить ни одного штриха, система MUST вернуть ошибку и MUST NOT сохранять пустое или частичное представление.
- **FR-010**: Система MUST сохранять полученный набор кривых непосредственно у записи слова (колонка `curve_points` существующей таблицы `words`), привязка только через первичный ключ слова (Id). Отдельная таблица для векторного представления MUST NOT создаваться.
- **FR-011**: Колонка `curve_points` MUST иметь тип `real[]`, используемый как трёхмерный массив вещественных чисел: `[кривая][точка 0..3][координата x/y]`; число кривых на слово переменное, число точек на кривую фиксировано (4).
- **FR-012**: Колонка `curve_points` MUST быть nullable: значение отсутствует до успешной векторизации слова.
- **FR-013**: Добавление колонки MUST быть оформлено отдельным изменением схемы через Liquibase changeset (принцип V конституции), с возможностью отката.
- **FR-014**: При ошибках на любом этапе до успешного завершения система MUST NOT оставлять частичную запись вектора; при повторной успешной векторизации система MUST заменять предыдущее представление целиком.
- **FR-015**: Числовые параметры векторизации (отступ фрагмента, погрешность аппроксимации) MUST читаться из конфигурации приложения.
- **FR-016**: Реализация MUST следовать паттернам проекта: тонкий контроллер, логика в сервисе со scoped DI, явные транзакции при мутациях, карта HTTP-ошибок из конституции (принцип III).

### Key Entities

- **Слово (Word)**: Существующая сущность распознанного слова на скане. Ключевые атрибуты для фичи: идентификатор, ссылка на скан, четыре вершины рамки, опциональное векторное представление штрихов (`curve_points`).
- **Скан (Scan)**: Владелец файла изображения и набора слов; файл скана — источник пикселей для извлечения фрагмента слова.
- **Векторное представление штрихов**: Набор кубических кривых Безье (каждая — 4 контрольные точки x,y), описывающих геометрию осевых линий штрихов слова. Хранится как атрибут слова, не как отдельная сущность. Порядок кривых в наборе на данном этапе не несёт семантики направления письма.
- **Параметры векторизации**: Конфигурируемые значения отступа при вырезке фрагмента и допустимой погрешности аппроксимации кривыми.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Для не менее чем 90% слов с читаемыми штрихами на тестовом наборе сканов успешный запрос векторизации завершается сохранением непустого набора кривых у соответствующей записи слова.
- **SC-002**: В 100% негативных сценариев (несуществующее слово, недоступный/повреждённый файл скана, фрагмент без штрихов) система возвращает ошибку и не создаёт пустое или частичное векторное представление.
- **SC-003**: Повторная успешная векторизация одного и того же слова оставляет ровно одно актуальное представление у записи (без дублирующих сущностей хранения) в 100% проверок.
- **SC-004**: Оператор может инициировать векторизацию слова и получить подтверждение успеха или понятную текстовую ошибку без ручных действий со схемой данных или файлами.
- **SC-005**: После применения изменения схемы новые записи слов допускают отсутствие векторного представления до векторизации, а успешно векторизованные слова сохраняют представление при последующем чтении записи.

## Assumptions

- Фича на данном этапе — серверный функционал. Endpoint: `POST /api/Scans/{id}/words/{wordId}/vectorize` (оба id обязательны; `wordId` без совпадения со сканом → 404). Отдельный UI-экран/кнопка на клиенте не входит в обязательный объём; контракт — plain-text ошибки, маршруты сканов/слов.
- Координаты контрольных точек кривых сохраняются относительно извлечённого и выровненного фрагмента слова (начало координат — фрагмент после выравнивания), а не в абсолютных координатах всего скана — этого достаточно для геометрического описания формы и будущего синтеза.
- При повторной успешной векторизации прежнее значение `curve_points` полностью заменяется; при ошибке повторной попытки прежнее успешное значение сохраняется.
- Отсутствие порядка/направления штрихов — осознанное ограничение offline-скана; нормализация stroke order — вне scope.
- Генерация почерка из текста (synthesis) — будущая цель и вне scope этой фичи; здесь только получение и сохранение геометрического представления.
- Параметры по умолчанию для отступа и погрешности будут заданы разумными значениями в конфигурации на этапе планирования/реализации; точные числа не фиксируются в спецификации.
- Карта HTTP-ошибок следует конституции: 404 для отсутствующего слова; тело — plain text на русском. Отсутствие файла скана на диске → 404 («Не найден файл»), по аналогии с выдачей изображения. Повреждённое/нечитаемое содержимое изображения → 400 с русским текстом причины. В обоих случаях `curve_points` не обновляется. «Нет штрихов» и прочие ошибки геометрии → 400 через `ArgumentException`.
- Изменение схемы — только новый Liquibase changeset; отдельная таблица для векторов не рассматривается.
