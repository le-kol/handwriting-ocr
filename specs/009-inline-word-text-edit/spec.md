# Feature Specification: Inline-редактирование текста слова в блоке результатов OCR

**Feature Branch**: `009-inline-word-text-edit`

**Created**: 2026-08-18

**Status**: Draft

**Input**: User description: "Inline-редактирование текста слова в блоке результатов OCR. Первый клик — выбор слова; второй клик по выбранному — редактирование на месте с автосохранением по Enter/blur и отменой по Escape. Без изменений backend/API; без регрессии DnD порядка слов, редактирования рамки на скане и остальных сценариев редактора."

## Clarifications

### Session 2026-08-18

- Q: Если автосохранение после inline-редактирования завершилось ошибкой, оставаться в inline-режиме или выходить из него? → A: Остаться в inline-режиме — введённый текст не теряется, показывается ошибка, повторная попытка по Enter/blur.
- Q: Что должна делать кнопка «Отмена» в панели, если слово в inline-режиме? → A: Полная отмена, как сейчас — выход из inline, закрытие панели, откат текста и координат к сохранённым на сервере.
- Q: Как отличить второй клик по выбранному слову от начала drag-and-drop? → A: Порог перемещения — клик без заметного смещения курсора открывает inline; drag начинается только после превышения порога.
- Q: Если слово выбрано кликом по рамке на скане, должен ли первый клик по слову в тексте открывать inline? → A: Да — один клик по слову в текстовом блоке открывает inline, если слово уже выбрано любым способом.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Быстрая правка текста слова на месте (Priority: P1)

Оператор просматривает распознанный текст построчно в текстовом блоке. Каждое слово кликабельно. Первым кликом оператор выбирает слово — оно подсвечивается в тексте, на скане показывается рамка, открывается панель редактирования. Вторым кликом по уже выбранному слову оператор переходит в режим inline-редактирования: на месте слова появляется поле ввода, курсор устанавливается в позицию, соответствующую месту клика. Оператор правит текст и завершает редактирование клавишей Enter или кликом вне поля; если текст изменился — изменения автоматически сохраняются на сервер.

**Why this priority**: Основная ценность фичи — сократить путь от обнаружения ошибки OCR до её исправления без переключения внимания на отдельное поле «Текст».

**Independent Test**: Выбрать слово одним кликом, вторым кликом войти в inline-режим, изменить текст, нажать Enter — текст в блоке и на сервере обновлён; панель редактирования остаётся открытой с актуальным текстом.

**Acceptance Scenarios**:

1. **Given** ни одно слово не выбрано, **When** оператор один раз кликает по слову в текстовом блоке, **Then** слово выбирается: подсветка в тексте, рамка на скане, открывается панель редактирования с полем «Текст» — поведение идентично текущему.
2. **Given** слово уже выбрано (первый клик выполнен), **When** оператор второй раз кликает по тому же слову в текстовом блоке, **Then** слово переходит в режим inline-редактирования: на месте слова отображается поле ввода с текущим текстом черновика; курсор устанавливается в позицию, соответствующую горизонтальному положению клика внутри слова.
2a. **Given** слово уже выбрано кликом по рамке на скане (без предшествующего клика по тексту), **When** оператор один раз кликает по этому слову в текстовом блоке без заметного смещения курсора, **Then** слово переходит в inline-режим — отдельный «первый клик по тексту для выбора» не требуется.
3. **Given** оператор находится в inline-режиме и изменил текст, **When** оператор нажимает Enter, **Then** inline-режим завершается; если текст отличается от последнего сохранённого на сервере значения — выполняется автоматическое сохранение; поле «Текст» в панели и отображение слова в текстовом блоке показывают сохранённый текст.
4. **Given** оператор находится в inline-режиме и изменил текст, **When** фокус покидает поле inline-ввода (blur), **Then** поведение совпадает с завершением по Enter: автосохранение при изменении текста, выход из inline-режима.
5. **Given** оператор находится в inline-режиме, но текст не менялся, **When** оператор нажимает Enter или фокус теряется, **Then** inline-режим завершается без запроса на сервер.
6. **Given** оператор находится в inline-режиме и изменил текст, **When** оператор нажимает Escape, **Then** inline-режим завершается без сохранения; текст слова возвращается к последнему сохранённому на сервере значению; поле «Текст» в панели синхронизировано с отменённым текстом.
7. **Given** оператор завершил inline-редактирование с изменённым текстом, **When** автосохранение завершилось ошибкой, **Then** inline-режим остаётся активным; введённый текст сохранён в поле inline-ввода и черновике; оператор видит сообщение об ошибке на русском языке; повторная попытка сохранения доступна по Enter или blur.

### User Story 2 - Согласованность с панелью редактирования (Priority: P1)

Панель редактирования с полем «Текст» и кнопкой «Сохранить» остаётся доступной и синхронизирована с inline-редактированием. Явное сохранение через кнопку «Сохранить» в панели по-прежнему требуется для правок, внесённых только в поле «Текст» без прохождения через inline-режим.

**Why this priority**: Оператор может комбинировать оба способа правки; рассинхрон между блоком текста и панелью недопустима.

**Independent Test**: Изменить текст inline и сохранить — поле «Текст» обновилось. Изменить текст только в поле «Текст» — inline не сохраняет автоматически; сохранение только по кнопке «Сохранить».

**Acceptance Scenarios**:

1. **Given** оператор изменил текст в inline-режиме и автосохранение успешно завершилось, **When** панель редактирования открыта, **Then** поле «Текст» показывает сохранённое значение; статус сохранения отображается в стиле существующего редактора («Сохранение», «Сохранено»).
2. **Given** слово выбрано, **When** оператор меняет текст только в поле «Текст» панели (не входя в inline-режим), **Then** автосохранение не выполняется; сохранение доступно только по кнопке «Сохранить», как сейчас.
3. **Given** оператор редактирует текст inline, **When** текст меняется посимвольно, **Then** поле «Текст» в панели отражает текущий черновик в реальном времени (до Enter/blur/Escape).
4. **Given** оператор изменил в панели несохранённые координаты рамки и затем сохранил текст через inline-автосохранение, **When** сохранение выполняется, **Then** на сервер отправляются актуальные текст и координаты черновика — как при обычном «Сохранить» слова.

### User Story 3 - Сохранение регрессий редактора (Priority: P1)

Существующие сценарии работы оператора продолжают работать без изменений: drag-and-drop порядка слов в текстовом блоке (включая drop на слово, на строку и межстрочные gap-зоны), редактирование рамки слова на скане, выбор слова кликом по рамке, добавление нового слова, распознавание, пакетная векторизация, удаление слова и скана.

**Why this priority**: Фича ускоряет правку текста, но не должна ломать уже отработанные потоки правки раскладки и рамок.

**Independent Test**: Выполнить регрессионный чек-лист из acceptance scenarios; каждый сценарий даёт результат, идентичный поведению до внедрения inline-редактирования.

**Acceptance Scenarios**:

1. **Given** слово не в inline-режиме, **When** оператор перетаскивает слова в recognized-text (drop на слово, строку, gap-зону), **Then** порядок и строки меняются как сейчас; inline-режим не активируется при drag.
2. **Given** слово уже выбрано и не в inline-режиме, **When** оператор нажимает на него в текстовом блоке без заметного смещения курсора, **Then** слово переходит в inline-режим, а не начинает drag-and-drop.
3. **Given** слово уже выбрано и не в inline-режиме, **When** оператор нажимает на него и перемещает курсор за порог смещения до отпускания, **Then** начинается drag-and-drop порядка слов; inline-режим не активируется.
4. **Given** слово выбрано, **When** оператор перемещает или правит углы рамки на скане, **Then** редактирование рамки работает как до фичи; сохранение координат — только по кнопке «Сохранить» в панели.
5. **Given** слово не выбрано, **When** оператор кликает по рамке на скане, **Then** слово выбирается; inline-режим не включается автоматически — для входа в inline требуется последующий клик по слову в текстовом блоке.
6. **Given** оператор добавляет новое слово, распознаёт скан, запускает пакетную векторизацию или удаляет слово/скан, **When** выполняет соответствующее действие, **Then** поведение совпадает с текущим редактором.
7. **Given** слово в inline-режиме, **When** оператор начинает перетаскивание этого слова, **Then** перетаскивание не конфликтует с полем ввода: drag-and-drop порядка слов не блокируется для других слов; для слова в inline-режиме перетаскивание не начинается до выхода из inline-режима.
8. **Given** слово в inline-режиме, **When** оператор нажимает «Отмена» в панели редактирования, **Then** inline-режим завершается; панель закрывается; текст и координаты слова откатываются к последним сохранённым на сервере значениям.

### Edge Cases

- Быстрый двойной клик по невыбранному слову: первый клик выбирает слово; второй клик (если слово уже выбрано) входит в inline-режим — не трактуется как начало drag-and-drop.
- Второй клик vs drag на уже выбранном слове: если курсор не смещается за порог перемещения, жест трактуется как вход в inline-режим; перетаскивание для смены порядка начинается только после превышения порога — DnD порядка слов не блокируется.
- Переключение на другое слово во время inline-редактирования: завершение inline-режима текущего слова по blur (с автосохранением при изменении текста), затем выбор нового слова первым кликом.
- Пустой текст после inline-правки: допускается сохранение пустой строки, если оператор явно очистил поле и подтвердил Enter/blur — поведение согласовано с полем «Текст» в панели.
- Ошибка автосохранения при завершении inline-редактирования: inline-режим остаётся активным; введённый текст не теряется (остаётся в inline-поле и черновике); оператор видит сообщение об ошибке на русском языке; повторная попытка сохранения — по Enter или blur.
- Новое несохранённое слово (без id на сервере): inline-редактирование текста доступно; автосохранение при изменении текста создаёт слово на сервере через существующую операцию сохранения нового слова.
- Одновременно изменены текст (inline) и координаты рамки (несохранённый черновик): автосохранение inline отправляет текст и текущие координаты черновика одним сохранением слова.
- Escape во время inline-редактирования отменяет только несохранённые правки текста; несохранённые изменения координат рамки в черновике не затрагиваются.
- Кнопка «Отмена» в панели во время inline-режима: полная отмена, как без inline — выход из inline-режима, закрытие панели, откат всего черновика слова (текст и координаты) к последним сохранённым на сервере значениям.
- Выбор слова кликом по рамке на скане не переводит слово в inline-режим; для входа в inline требуется клик по слову в текстовом блоке — если слово уже выбрано (в том числе по рамке), достаточно одного такого клика.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Первый клик по слову в текстовом блоке MUST выполнять выбор слова с текущим поведением: подсветка в тексте, рамка на скане, открытие панели редактирования.
- **FR-002**: Клик по уже выбранному слову в текстовом блоке MUST переводить это слово в режим inline-редактирования с полем ввода на месте слова; «уже выбранным» считается слово, выбранное любым способом (клик по тексту, клик по рамке на скане или иной существующий способ выбора).
- **FR-003**: При входе в inline-режим система MUST установить курсор в позицию, соответствующую горизонтальному положению второго клика внутри слова.
- **FR-004**: Завершение inline-редактирования по Enter или при потере фокуса (blur) MUST выводить слово из inline-режима; если текст изменился относительно последнего сохранённого на сервере значения — MUST выполняться автоматическое сохранение на сервер.
- **FR-005**: Если при завершении inline-редактирования текст не изменился, система MUST выйти из inline-режима без запроса на сервер.
- **FR-006**: Клавиша Escape во время inline-редактирования MUST отменять несохранённые правки текста, восстанавливать последнее сохранённое на сервере значение и выходить из inline-режима без сохранения.
- **FR-007**: Во время inline-редактирования изменения текста MUST синхронно отражаться в поле «Текст» панели редактирования.
- **FR-008**: Поле «Текст» в панели редактирования MUST NOT получать автосохранение; явная кнопка «Сохранить» MUST оставаться единственным способом сохранить правки, внесённые только через панель без inline-режима.
- **FR-009**: Автосохранение inline MUST использовать существующую операцию сохранения слова (текст и координаты четырёх вершин рамки из текущего черновика); backend, API и схема данных MUST NOT изменяться.
- **FR-010**: Одновременное inline-редактирование нескольких слов MUST NOT поддерживаться; в каждый момент не более одного слова может находиться в inline-режиме.
- **FR-011**: Drag-and-drop порядка слов в recognized-text (drop на слово, на строку, межстрочные gap-зоны) MUST работать без регрессии и MUST NOT конфликтовать с inline-редактированием.
- **FR-012**: Редактирование рамки слова на скане (перемещение и углы), выбор слова кликом по рамке, добавление нового слова, распознавание, пакетная векторизация, удаление слова и скана MUST сохранять текущее поведение без регрессий.
- **FR-013**: Редактирование векторного представления (curvePoints) MUST NOT входить в объём; автоматический пересчёт векторизации после inline-сохранения текста MUST NOT выполняться.
- **FR-014**: Сообщения о сохранении, успехе и ошибках при inline-автосохранении MUST отображаться на русском языке в стиле существующего редактора.
- **FR-015**: При ошибке inline-автосохранения система MUST оставлять слово в inline-режиме с сохранённым введённым текстом; оператор MUST иметь возможность повторить сохранение по Enter или blur без повторного входа в inline-режим.
- **FR-016**: Кнопка «Отмена» в панели редактирования во время inline-режима MUST выполнять полную отмену черновика слова: выход из inline-режима, закрытие панели, откат текста и координат рамки к последним сохранённым на сервере значениям — поведение MUST совпадать с «Отмена» без inline-режима.
- **FR-017**: Для уже выбранного слова в текстовом блоке система MUST трактовать короткий клик без заметного смещения курсора как вход в inline-режим; начало drag-and-drop порядка слов MUST происходить только после превышения порога перемещения курсора от точки нажатия.

### Key Entities

- **Слово (черновик)**: Единица распознанного текста с текстом, четырьмя вершинами рамки, индексами строки и порядка; может быть сохранённым или новым черновиком. Текст в черновике может редактироваться inline или через панель.
- **Inline-редактирование**: Временный режим одного выбранного слова в текстовом блоке, при котором слово заменяется полем ввода на месте отображения; завершается Enter, blur или Escape.
- **Текстовый блок recognized-text**: Построчное отображение распознанного текста с кликабельными и перетаскиваемыми словами; единственное место входа в inline-режим (второй клик по выбранному слову).
- **Панель редактирования**: Область с полем «Текст», координатами рамки и кнопками «Сохранить» / «Отмена»; остаётся открытой при inline-редактировании и синхронизируется с черновиком.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Оператор может исправить текст выбранного слова inline (выбор → второй клик → правка → Enter) не более чем за 5 секунд в 95% пробных сценариев без обращения к полю «Текст» в панели.
- **SC-002**: В 100% проверенных сценариев inline-автосохранения текст на сервере после успешного сохранения совпадает с текстом, видимым в текстовом блоке; после перезагрузки скана текст сохранён.
- **SC-003**: В регрессионной проверке все сценарии из FR-011 и FR-012 (DnD порядка, gap-зоны, рамка на скане, выбор по рамке, добавление/распознавание/векторизация/удаление) проходят без отличий от поведения до внедрения фичи.
- **SC-004**: Не менее 90% операторов, знакомых с текущим редактором, успешно выполняют inline-правку текста с первой попытки без инструкций.
- **SC-005**: При завершении inline-редактирования без изменения текста система не выполняет лишних запросов на сервер (0 запросов на сохранение в сценарии «текст не менялся»).

## Assumptions

- Целевой пользователь — оператор редактора сканов с мышью и клавиатурой; touch-специфичные жесты вне scope.
- Inline-режим — однострочное поле ввода; Enter завершает редактирование, многострочный ввод не требуется.
- Второй клик для входа в inline-режим доступен только в текстовом блоке, не на рамке скана; если слово уже выбрано (включая выбор по рамке), первый клик по нему в текстовом блоке открывает inline-режим.
- При blur inline-поля из-за выбора другого слова сначала применяется логика завершения inline-редактирования текущего слова (автосохранение при изменении), затем выполняется выбор нового слова.
- Сохранение нового слова (без id) через inline-автосохранение следует существующему потоку создания слова с последующей подстановкой id в локальную раскладку.
- Поле «Текст» в панели и inline-поле редактируют один и тот же черновик; координаты рамки при inline-автосохранении берутся из текущего черновика без изменения lineIndex/orderIndex.
- curvePoints и результаты векторизации после inline-сохранения текста не пересчитываются автоматически.
