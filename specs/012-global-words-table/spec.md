# Feature Specification: Глобальная таблица слов и экспорт датасета

**Feature Branch**: `012-global-words-table`

**Created**: 2026-08-21

**Status**: Draft

**Input**: User description: "Добавить на фронтенде новый экран «Таблица слов»: единый список всех слов из всех сканов (не привязанный к конкретному скану), с текстовым поиском по слову, фильтром по статусу векторизации (векторизовано / не векторизовано) и фильтром по скану. Таблица показывает как минимум: текст слова, id скана, статус векторизации, миниатюру вектора для векторизованных слов (существующий компонент WordCurveThumbnail). Клик по строке ведёт на существующий редактор скана с выбранным словом. Таблица должна поддерживать постраничную навигацию. Так как сейчас нет способа получить слова сразу всех сканов одним запросом (только GET /api/Scans/{id}/words по одному скану), нужен новый read-only backend endpoint для получения слов кросс-сканово, с поддержкой серверной пагинации, поиска по тексту и фильтра по статусу векторизации/скану. Существующие endpoint'ы работы со словом (создание, обновление, удаление, векторизация одиночная и batch) не меняются. Дополнительно: на той же странице добавить две отдельные кнопки экспорта датасета для последующего offline ML-пайплайна (кластеризация штрихов на буквы, затем обучение генеративной модели рукописных штрихов): «Экспортировать всё» — выгружает все векторизованные слова из всех сканов, независимо от текущих значений поиска и фильтров в таблице. «Экспортировать отфильтрованное» — выгружает только слова, попадающие под текущие активные поиск/фильтры таблицы (тот же набор, что оператор видит постранично на экране, но не только текущая страница — весь отфильтрованный набор целиком). Обе кнопки формируют файл одинакового формата, различие только в наборе слов, попадающих в выгрузку. Если отфильтрованный набор пуст, кнопка «Экспортировать отфильтрованное» неактивна или явно сообщает, что нет слов для экспорта, без ошибки интерфейса. Экспорт выполняется целиком на фронтенде: клиент загружает данные слов через endpoint(ы) чтения слов (постранично, пока не будут получены все нужные слова для выбранного вида экспорта), фильтрует только слова с непустым и валидным curvePoints, формирует файл в формате JSONL (одна строка — одно слово, аналогично isWordVectorized/filterValidCurves для критерия «векторизовано») и инициирует скачивание файла в браузере (Blob + ссылка на скачивание), без отправки данных куда-либо ещё. Формат одной строки экспорта — JSON-объект с полями: wordId (число), scanId (число), text (строка, распознанный текст слова), curves — массив кривых слова как есть из curvePoints (массив кривых, каждая — 4 точки [x,y], в системе координат фрагмента слова), без разделения на штрихи, без сведений о порядке нанесения штрихов и без параметров векторизации (paddingPx, approximationTolerance) — эти данные не нужны и не включаются. Экспорт должен: пропускать слова с пустым или невалидным curvePoints без ошибки всего экспорта; сформировать один файл на каждый вид экспорта (например, words-dataset-all.jsonl и words-dataset-filtered.jsonl) и скачать его через браузер; показать оператору количество экспортированных слов после завершения каждого экспорта и понятное текстовое сообщение об ошибке, если загрузка данных для экспорта не удалась; не блокировать использование таблицы (поиск, фильтры, пагинацию) во время выполнения экспорта, либо явно блокировать только соответствующую кнопку экспорта на время его выполнения. Backend для этой фичи меняется минимально: только новый read-only endpoint(ы) для получения слов кросс-сканово с пагинацией/поиском/фильтрами, без изменений схемы БД, без изменений формата слова, без изменений существующих операций записи (создание/обновление/удаление/векторизация слова)."

## Clarifications

### Session 2026-08-21

- Q: Как пользователь переключается между экраном «Таблица слов», списком сканов и редактором скана после клика по строке таблицы? → A: Два экрана с переключателем («Сканы» / «Слова»); каждый открывается отдельной кнопкой; при загрузке приложения по умолчанию активен экран «Сканы»; клик по строке таблицы слов переключает на экран «Сканы» и открывает редактор с выбранным словом.
- Q: В каком порядке строки должны быть отсортированы в глобальной таблице слов по умолчанию? → A: `scanId` по возрастанию, затем `orderIndex` внутри скана (порядок чтения).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Просмотр и поиск слов по всем сканам (Priority: P1)

Оператор открывает новый экран «Таблица слов» и видит единый список всех слов из всех сканов системы — не привязанный к одному выбранному скану. В таблице отображаются как минимум: распознанный текст слова, идентификатор скана, статус векторизации (векторизовано / не векторизовано) и миниатюра формы штрихов для векторизованных слов. Оператор может ввести текстовый поиск по слову, выбрать фильтр по статусу векторизации и фильтр по конкретному скану; таблица показывает только подходящие записи. Список разбит на страницы с постраничной навигацией.

**Why this priority**: Без кросс-сканового обзора и фильтрации невозможен контроль качества векторизации и подготовка данных по всей базе; это ядро экрана.

**Independent Test**: Открыть экран «Таблица слов» при наличии слов в нескольких сканах; применить поиск, фильтр по статусу и фильтр по скану; убедиться, что таблица показывает корректный подмножество с пагинацией и миниатюрами только у векторизованных строк.

**Acceptance Scenarios**:

1. **Given** в системе есть слова из нескольких сканов, **When** оператор открывает экран «Таблица слов», **Then** таблица показывает слова из всех сканов с колонками: текст, идентификатор скана, статус векторизации; для векторизованных слов — миниатюра формы штрихов, для невекторизованных — пустая ячейка или нейтральный маркер без ложной геометрии.
2. **Given** оператор вводит текст в поле поиска, **When** поиск применён, **Then** в таблице остаются только слова, чей распознанный текст соответствует запросу (подстрока без учёта регистра — см. Assumptions).
3. **Given** оператор выбирает фильтр «векторизовано» или «не векторизовано», **When** фильтр активен, **Then** таблица показывает только слова с выбранным статусом; статус определяется по наличию непустого валидного векторного представления (критерий как у существующей логики «векторизовано» в приложении).
4. **Given** оператор выбирает фильтр по конкретному скану, **When** фильтр активен, **Then** таблица показывает только слова этого скана.
5. **Given** результатов больше, чем помещается на одну страницу, **When** оператор переключает страницы, **Then** отображается следующая или предыдущая порция записей; номер страницы и общее количество страниц (или эквивалентная навигация) понятны оператору.
6. **Given** комбинация поиска и фильтров не даёт ни одной записи, **When** таблица обновлена, **Then** оператор видит понятное пустое состояние без ошибки интерфейса.

### User Story 2 - Переход к редактированию слова в контексте скана (Priority: P1)

Оператор на экране «Слова» кликает по строке таблицы — приложение переключается на экран «Сканы» и открывает существующий редактор соответствующего скана с тем же словом уже выбранным, как если бы оператор открыл скан и кликнул по слову в тексте или рамке. Вернуться к таблице слов можно кнопкой переключения на экран «Слова».

**Why this priority**: Таблица должна быть рабочим инструментом навигации, а не изолированным списком; без перехода к редактору ценность обзора резко падает.

**Independent Test**: На экране «Слова» кликнуть строку слова из известного скана; убедиться, что активен экран «Сканы», открыт редактор этого скана и панель редактирования выбранного слова активна.

**Acceptance Scenarios**:

1. **Given** оператор на экране «Слова», **When** он кликает по строке слова с известными `scanId` и `wordId`, **Then** приложение переключается на экран «Сканы», открывается редактор скана для этого `scanId`, слово с данным `wordId` выбрано (панель редактирования слова доступна).
2. **Given** оператор перешёл из таблицы слов в редактор, **When** он нажимает кнопку переключения на экран «Слова», **Then** снова отображается экран «Таблица слов» (без регрессии экрана «Сканы» и его функций).

### User Story 3 - Экспорт полного датасета векторизованных слов (Priority: P2)

Оператор нажимает «Экспортировать всё» и получает один файл формата JSONL со всеми векторизованными словами из всех сканов — независимо от текущих значений поиска и фильтров в таблице. Каждая строка файла — одно слово с полями: идентификатор слова, идентификатор скана, номер строки слова в раскладке скана, распознанный текст, массив кривых в системе координат фрагмента слова. Слова с пустым или невалидным векторным представлением пропускаются без прерывания всего экспорта. После успешного завершения оператор видит количество экспортированных слов.

**Why this priority**: Полная выгрузка нужна для offline ML-пайплайна (кластеризация штрихов, обучение генеративной модели); это основной сценарий подготовки датасета.

**Independent Test**: При наличии векторизованных слов в нескольких сканах нажать «Экспортировать всё»; проверить скачанный файл `words-dataset-all.jsonl`, число строк и сообщение о количестве экспортированных записей.

**Acceptance Scenarios**:

1. **Given** в системе есть векторизованные слова в одном или нескольких сканах, **When** оператор нажимает «Экспортировать всё», **Then** браузер скачивает один файл `words-dataset-all.jsonl`; каждая строка — валидный JSON-объект с полями `wordId`, `scanId`, `lineIndex`, `text`, `curves`.
2. **Given** экспорт выполняется, **When** часть слов имеет пустое или невалидное векторное представление, **Then** такие слова пропускаются; остальные включаются в файл; экспорт не завершается ошибкой целиком из-за отдельных пропусков.
3. **Given** экспорт успешно завершён, **When** оператор смотрит на интерфейс, **Then** отображается понятное сообщение с количеством экспортированных слов.
4. **Given** активны поиск или фильтры в таблице, **When** оператор нажимает «Экспортировать всё», **Then** в файл попадают все векторизованные слова системы, а не только видимая страница и не только отфильтрованный набор.
5. **Given** поле `curves` в строке экспорта, **When** файл просмотрен, **Then** массив содержит кривые слова как в сохранённом векторном представлении (каждая кривая — 4 точки `[x, y]`); нет полей параметров векторизации, порядка штрихов и разбиения на штрихи.

### User Story 4 - Экспорт отфильтрованного датасета (Priority: P2)

Оператор настраивает поиск и фильтры в таблице и нажимает «Экспортировать отфильтрованное». Система формирует файл того же формата JSONL (`words-dataset-filtered.jsonl`), но только для слов, попадающих под текущие активные поиск и фильтры таблицы — весь отфильтрованный набор целиком, а не только текущая страница. Из этого набора в файл попадают только векторизованные слова с валидным векторным представлением. Если отфильтрованный набор пуст или не содержит ни одного экспортируемого векторизованного слова, кнопка неактивна или явно сообщает об отсутствии данных для экспорта — без ошибки интерфейса.

**Why this priority**: Позволяет готовить целевые подмножества датасета (например, один скан или подстрока текста) без ручной фильтрации файла offline.

**Independent Test**: Задать фильтр по скану и поиск; нажать «Экспортировать отфильтрованное»; убедиться, что файл содержит только слова, соответствующие фильтрам, и только векторизованные записи.

**Acceptance Scenarios**:

1. **Given** оператор задал поиск и/или фильтры, и отфильтрованный набор содержит векторизованные слова, **When** он нажимает «Экспортировать отфильтрованное», **Then** скачивается `words-dataset-filtered.jsonl` с записями только из отфильтрованного набора и только для векторизованных слов с валидным представлением.
2. **Given** отфильтрованный набор пуст или не содержит экспортируемых векторизованных слов, **When** оператор смотрит на кнопку «Экспортировать отфильтрованное», **Then** кнопка недоступна или сопровождается явным пояснением «нет слов для экспорта»; нажатие не приводит к ошибке интерфейса.
3. **Given** экспорт отфильтрованного набора успешен, **When** оператор читает сообщение в интерфейсе, **Then** указано количество экспортированных слов.
4. **Given** экспорт отфильтрованного набора выполняется, **When** оператор продолжает пользоваться таблицей, **Then** поиск, фильтры и пагинация остаются доступны; блокируется только соответствующая кнопка экспорта (или эквивалентное ограничение только на время её операции).

### User Story 5 - Надёжная загрузка данных для таблицы и экспорта (Priority: P1)

Система предоставляет единую read-only операцию чтения слов кросс-сканово с серверной пагинацией, текстовым поиском и фильтрами по статусу векторизации и скану. Экран таблицы и оба вида экспорта используют эту операцию (экспорт — последовательными страницами до полного набора). Существующие операции создания, обновления, удаления и векторизации слов не изменяются.

**Why this priority**: Без серверного кросс-сканового чтения ни таблица, ни экспорт не могут работать корректно при большом объёме данных; ограничение «только read-only endpoint» — явное требование заказчика.

**Independent Test**: Запросить страницу слов с комбинацией фильтров через новую операцию чтения; убедиться, что ответ согласован с данными отдельных сканов и что мутационные операции слова работают как до фичи.

**Acceptance Scenarios**:

1. **Given** в системе слова в нескольких сканах, **When** клиент запрашивает страницу кросс-сканового списка с параметрами поиска и фильтров, **Then** сервер возвращает только подходящие записи для запрошенной страницы и метаданные пагинации (номер страницы, размер страницы, общее число записей или эквивалент).
2. **Given** клиент выполняет экспорт, **When** ему нужен полный или отфильтрованный набор, **Then** он последовательно запрашивает все страницы с соответствующими параметрами, пока не получит весь набор; данные никуда, кроме локального формирования файла в браузере, не отправляются.
3. **Given** загрузка данных для экспорта прервана ошибкой сети или сервера, **When** операция завершается неуспешно, **Then** оператор видит понятное текстовое сообщение об ошибке; частично сформированный файл не выдаётся как успешный результат.
4. **Given** фича развёрнута, **When** выполняются существующие операции над словом (создание, обновление, удаление, одиночная и пакетная векторизация), **Then** их поведение и контракты не изменены.

### Edge Cases

- В системе нет ни одного слова: таблица показывает пустое состояние; обе кнопки экспорта недоступны или сообщают об отсутствии данных.
- Все слова невекторизованы: таблица работает; «Экспортировать всё» завершается с нулём экспортированных записей и понятным сообщением; «Экспортировать отфильтрованное» — аналогично при отсутствии векторизованных в наборе.
- Очень длинный текст поиска или спецсимволы: поиск не ломает интерфейс; при отсутствии совпадений — пустое состояние.
- Скан удалён, пока открыта таблица: при обновлении списка записи удалённого скана исчезают; переход по устаревшей строке обрабатывается с понятным сообщением (скан или слово не найдено).
- Параллельный запуск двух экспортов: каждая кнопка блокируется независимо на время своей операции; таблица остаётся интерактивной.
- Слово помечено векторизованным в таблице, но при экспорте `curvePoints` оказывается невалидным: слово пропускается в файле; общий экспорт успешен; счётчик отражает только реально записанные строки.
- Одновременное изменение слова в редакторе и просмотр таблицы: после возврата на таблицу или смены страницы данные соответствуют актуальному состоянию сервера.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Приложение MUST предоставить отдельный экран «Таблица слов» («Слова») с единым списком слов из всех сканов, не привязанным к одному выбранному скану; экран MUST быть равноправным экрану «Сканы» и переключаться отдельной кнопкой; при первой загрузке приложения MUST быть активен экран «Сканы».
- **FR-002**: Таблица MUST отображать как минимум: распознанный текст слова, идентификатор скана, статус векторизации (векторизовано / не векторизовано), миниатюру формы штрихов для векторизованных слов (переиспользование существующего компонента миниатюры вектора).
- **FR-003**: Экран MUST поддерживать текстовый поиск по распознанному тексту слова, фильтр по статусу векторизации (векторизовано / не векторизовано / все) и фильтр по скану.
- **FR-004**: Таблица MUST поддерживать постраничную навигацию с серверной пагинацией (клиент запрашивает одну страницу за раз, не загружая все слова сразу для отображения).
- **FR-005**: Клик по строке таблицы на экране «Слова» MUST переключать приложение на экран «Сканы» и открывать существующий редактор соответствующего скана с выбранным словом из этой строки.
- **FR-006**: Система MUST предоставить новую read-only операцию получения слов кросс-сканово с поддержкой серверной пагинации, текстового поиска, фильтра по статусу векторизации и фильтра по идентификатору скана.
- **FR-007**: Ответ read-only операции MUST содержать данные слова в том же формате, что и существующее чтение слов скана (включая векторное представление для отображения миниатюры и экспорта), плюс метаданные пагинации.
- **FR-008**: Фича MUST NOT изменять схему базы данных, формат сущности «слово» и существующие операции записи над словом (создание, обновление, удаление, одиночная и пакетная векторизация).
- **FR-009**: На экране «Таблица слов» MUST быть две отдельные кнопки: «Экспортировать всё» и «Экспортировать отфильтрованное».
- **FR-010**: «Экспортировать всё» MUST формировать и скачивать файл `words-dataset-all.jsonl` со всеми векторизованными словами всех сканов, игнорируя текущие поиск и фильтры таблицы.
- **FR-011**: «Экспортировать отфильтрованное» MUST формировать и скачивать файл `words-dataset-filtered.jsonl` только для слов, попадающих под текущие активные поиск и фильтры таблицы (весь отфильтрованный набор, не только текущая страница).
- **FR-012**: Оба вида экспорта MUST выполняться целиком на стороне клиента: последовательная загрузка страниц через read-only операцию чтения, локальная фильтрация и формирование файла без отправки данных на другие сервисы.
- **FR-013**: Каждая строка экспорта MUST быть JSON-объектом с полями: `wordId` (число), `scanId` (число), `lineIndex` (число, номер строки слова в раскладке скана), `text` (строка), `curves` (массив кривых; каждая кривая — 4 точки `[x, y]` в системе координат фрагмента слова); MUST NOT включать параметры векторизации, порядок штрихов и разбиение на штрихи.
- **FR-014**: Экспорт MUST включать только слова, у которых после проверки валидности векторного представления остаётся хотя бы одна валидная кривая (критерий эквивалентен существующей логике «векторизовано» в клиенте); слова с пустым или невалидным представлением MUST пропускаться без ошибки всего экспорта.
- **FR-015**: После успешного экспорта MUST отображаться количество экспортированных слов; при ошибке загрузки данных MUST отображаться понятное текстовое сообщение на русском языке.
- **FR-016**: Если отфильтрованный набор пуст или не содержит экспортируемых векторизованных слов, кнопка «Экспортировать отфильтрованное» MUST быть неактивна или явно сообщать об отсутствии данных — без ошибки интерфейса.
- **FR-017**: Во время выполнения экспорта MUST NOT блокироваться поиск, фильтры и пагинация таблицы; MAY блокироваться только нажатая кнопка экспорта на время соответствующей операции.
- **FR-018**: Критерий «векторизовано» для статуса в таблице и для отбора в экспорт MUST быть согласован: наличие хотя бы одной валидной кривой в сохранённом векторном представлении слова.

### Key Entities

- **Слово (кросс-скановый вид)**: Распознанная единица текста с идентификатором, привязкой к скану, опциональным векторным представлением штрихов; отображается в глобальной таблице и может быть экспортировано.
- **Скан**: Документ-владелец слова; используется как фильтр таблицы и поле `scanId` в экспорте.
- **Запись таблицы**: Строка с текстом, идентификатором скана, статусом векторизации и опциональной миниатюрой.
- **Параметры списка**: Поисковая строка, фильтр статуса векторизации, фильтр скана, номер страницы — определяют подмножество для таблицы и для «Экспортировать отфильтрованное».
- **Строка датасета (экспорт)**: JSON-объект `{ wordId, scanId, lineIndex, text, curves }` в файле JSONL для offline ML-пайплайна.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Оператор может найти слово по тексту и ограничить выборку сканом и статусом векторизации не более чем за 4 действия (открыть экран → ввести поиск → выбрать фильтры → увидеть результат).
- **SC-002**: При объёме данных, превышающем один экран, оператор может последовательно просмотреть все страницы отфильтрованного набора; время отклика при переключении страницы остаётся приемлемым для интерактивной работы (не более нескольких секунд при типичном объёме данных проекта).
- **SC-003**: В 100% проверок клик по строке таблицы открывает редактор правильного скана с выбранным словом из строки.
- **SC-004**: «Экспортировать всё» включает все векторизованные слова системы с валидным представлением; при контрольной выборке ни одно такое слово не отсутствует в файле.
- **SC-005**: «Экспортировать отфильтрованное» включает только слова, соответствующие активным поиску и фильтрам, и только векторизованные с валидным представлением; при контрольной выборке лишние записи отсутствуют.
- **SC-006**: После каждого успешного экспорта оператор видит точное количество записей, записанных в файл; при сбое загрузки — текстовое сообщение об ошибке в 100% случаев.
- **SC-007**: Существующие сценарии редактирования, векторизации и удаления слова в редакторе скана работают без регрессии после внедрения фичи.
- **SC-008**: Экспорт большого набора (тысячи слов) не делает таблицу полностью неинтерактивной: поиск и смена страницы остаются доступны во время фоновой выгрузки.

## Assumptions

- Целевой пользователь — тот же оператор, что работает с редактором сканов; отдельные роли и права доступа не вводятся.
- Навигация: два экрана — «Сканы» (таблица сканов и редактор) и «Слова» (глобальная таблица слов); каждый открывается отдельной кнопкой-переключателем; при загрузке приложения по умолчанию активен экран «Сканы»; на экране «Слова» одновременно видна только таблица слов (без редактора скана).
- Поиск по тексту слова — подстрока без учёта регистра; спецсимволы в запросе не должны ломать интерфейс (экранирование на стороне сервера при необходимости).
- Фильтр «все статусы» — значение по умолчанию; фильтр по скану включает опцию «все сканы».
- Размер страницы таблицы согласован с существующими списками в приложении или задаётся разумным фиксированным значением (например, 25–50 записей); одинаков для отображения и для последовательной загрузки при экспорте.
- Статус «векторизовано» и отбор кривых для экспорта используют ту же семантику, что существующие функции проверки валидности кривых и признака векторизации в клиенте (непустой массив кривых, каждая кривая — ровно 4 точки с конечными координатами).
- Поле `curves` в экспорте — отфильтрованный массив валидных кривых из сохранённого векторного представления слова, без дополнительных преобразований координат.
- Список сканов для фильтра загружается существующей операцией перечисления сканов (с пагинацией при необходимости); отдельный endpoint только для имён сканов не обязателен, если идентификатор скана достаточен для фильтра.
- По умолчанию (без явной сортировки оператором) записи в таблице и в порядке чтения страниц для экспорта отсортированы по `scanId` по возрастанию, затем по `orderIndex` слова внутри скана (порядок чтения скана); это обеспечивает стабильную пагинацию при неизменном наборе данных.
- Поле `lineIndex` в экспорте — существующий номер строки слова в раскладке OCR скана (то же значение, что уже хранится и возвращается для слова в текущем API), без пересчёта или изменения семантики.
- Read-only операция кросс-сканового чтения — единственное изменение серверного API в рамке фичи; может быть один endpoint или минимальный набор, если контракт пагинации/фильтров один.
- Сообщения интерфейса и ошибок — на русском языке, в духе текущего UX проекта.
- Offline ML-пайплайн, кластеризация штрихов и обучение модели — вне scope; фича только готовит JSONL-файл для последующего использования.
- Изменение порядка колонок, сортировка по произвольным полям и массовые операции над словами из таблицы — вне scope, если явно не запрошены позже.
