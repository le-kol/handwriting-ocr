# Feature Specification: Вставка слова на новую строку через drag-and-drop

**Feature Branch**: `007-dnd-new-line-gaps`

**Created**: 2026-08-17

**Status**: Draft

**Input**: User description: "Расширить drag-and-drop в текстовом блоке recognized-text: добавить вставку слова на новую строку. Уже работает: drop на слово → вставка перед словом; drop на строку → в конец строки. Нужно добавить drop в зоны над первой строкой, между строками и под последней строкой. Backend не менять. Изменения только в локальной раскладке до «Сохранить порядок». UX: межстрочные gap-зоны с подсветкой при drag-over, без конфликта с существующим DnD, сообщения на русском."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Новая строка в начале документа (Priority: P1)

Оператор перетаскивает слово из текстового блока распознанного текста и отпускает его в зону над первой строкой. Слово оказывается единственным на новой строке в самом начале документа; прежняя первая строка сдвигается ниже.

**Why this priority**: Позволяет вынести слово в начало текста без обходных манёвров; критично для корректной правки порядка чтения.

**Independent Test**: Открыть скан с несколькими строками, перетащить слово из середины документа в верхнюю gap-зону — слово появляется на отдельной первой строке; остальной текст сохраняет относительный порядок.

**Acceptance Scenarios**:

1. **Given** документ содержит две и более строки слов, **When** оператор перетаскивает слово и отпускает его в зону над первой строкой, **Then** слово отображается на новой строке перед всеми существующими строками.
2. **Given** оператор наводит перетаскиваемое слово на зону над первой строкой, **When** курсор находится над этой зоной, **Then** зона визуально подсвечивается (горизонтальная линия-индикатор места вставки).
3. **Given** локальная раскладка изменена переносом в начало, **When** оператор ещё не нажимал «Сохранить порядок», **Then** изменение видно только в интерфейсе; данные на сервере не меняются.

---

### User Story 2 - Новая строка между существующими строками (Priority: P1)

Оператор перетаскивает слово и отпускает его в gap-зону между строкой N и строкой N+1. Слово появляется на отдельной новой строке строго между ними.

**Why this priority**: Основной сценарий разрыва строки — перенос одного слова на отдельную строку внутри текста.

**Independent Test**: Перетащить слово из строки 2 в gap между строками 1 и 2 — слово оказывается на новой строке между ними; порядок слов внутри нетронутых строк не меняется.

**Acceptance Scenarios**:

1. **Given** документ содержит минимум две строки, **When** оператор отпускает слово в gap-зону между строкой N и строкой N+1, **Then** слово отображается на новой строке между этими строками как единственное (или первое) слово этой строки.
2. **Given** оператор перетаскивает слово над gap-зоной между строками, **When** курсор в пределах hit-area зоны, **Then** активная gap-зона подсвечивается горизонтальной линией; остальные gap-зоны не подсвечены.
3. **Given** оператор отпускает слово в gap между двумя строками, **When** drop завершён, **Then** существующие сценарии drop на слово (вставка перед словом) и drop на строку (в конец строки) по-прежнему работают без регрессии.

---

### User Story 3 - Новая строка в конце документа (Priority: P1)

Оператор перетаскивает слово и отпускает его в зону под последней строкой. Слово появляется на новой строке в конце документа.

**Why this priority**: Симметрично вставке в начало; нужно для переноса слова в конец текста отдельной строкой.

**Independent Test**: Перетащить слово из первой строки в нижнюю gap-зону — слово на отдельной последней строке.

**Acceptance Scenarios**:

1. **Given** документ содержит одну или более строк, **When** оператор отпускает слово в зону под последней строкой, **Then** слово отображается на новой строке после всех существующих строк.
2. **Given** оператор наводит слово на нижнюю gap-зону, **When** курсор над зоной, **Then** зона подсвечивается горизонтальной линией.

---

### User Story 4 - Сохранение существующего drag-and-drop (Priority: P1)

Оператор по-прежнему может перетаскивать слова внутри и между строками способами, которые работали до фичи: отпускание на слово вставляет слово перед ним (включая начало строки при drop на первое слово); отпускание на область строки без попадания в gap вставляет слово в конец этой строки.

**Why this priority**: Новые gap-зоны не должны ломать уже отработанный UX редактирования раскладки.

**Independent Test**: Выполнить drop на первое слово строки, drop на середину строки (не gap), drop на пустую область строки — поведение совпадает с текущим до внедрения gap-зон.

**Acceptance Scenarios**:

1. **Given** оператор отпускает слово непосредственно на другое слово, **When** drop завершён, **Then** перетаскиваемое слово вставляется перед целевым словом в той же строке.
2. **Given** оператор отпускает слово на область строки (не на gap и не на конкретное слово), **When** drop завершён, **Then** слово добавляется в конец этой строки.
3. **Given** локальный порядок изменён любым из способов DnD, **When** оператор нажимает «Сохранить порядок», **Then** на сервер отправляется актуальная раскладка строк; при успехе отображается сообщение «Порядок сохранён» на русском языке.

---

### Edge Cases

- Перетаскивание единственного слова документа в gap-зону рядом с его текущей позицией: раскладка остаётся логически корректной (без «пустых» строк в отображении).
- Документ из одной строки: доступны gap над строкой, под строкой; drop между строками недоступен (нет пары соседних строк).
- Перетаскивание слова на gap, который граничит с исходной строкой этого слова: слово переносится на новую строку; исходная строка не содержит «дыр» или артеfact-пустых строк.
- Одновременная подсветка: при drag-over активна только одна gap-зона — та, над которой находится курсор.
- Gap-зона имеет достаточную hit-area для попадания указателем без точного прицеливания в один пиксель.
- Несохранённое слово (черновик без id в системе): правила сохранения порядка («Сначала сохраните новое слово») не меняются; DnD для такого слова ведёт себя согласованно с остальными словами.
- Отмена редактирования («Отмена»): локальная раскладка и состояние перетаскивания сбрасываются к данным сервера, как до фичи.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система MUST предоставлять отдельные drop-зоны (gap) над первой строкой, между каждой парой соседних строк и под последней строкой текстового блока распознанного текста.
- **FR-002**: Система MUST при drop в gap-зону над первой строкой помещать перетаскиваемое слово на новую строку в начале документа.
- **FR-003**: Система MUST при drop в gap-зону между строкой N и строкой N+1 помещать перетаскиваемое слово на новую строку между ними.
- **FR-004**: Система MUST при drop в gap-зону под последней строкой помещать перетаскиваемое слово на новую строку в конце документа.
- **FR-005**: Система MUST сохранять без изменений поведение drop на слово (вставка перед целевым словом) и drop на область строки (вставка в конец строки).
- **FR-006**: Система MUST обрабатывать события drop в gap-зонах так, чтобы они не перехватывались и не конфликтовали с drop на слова и строки.
- **FR-007**: Система MUST подсвечивать активную gap-зону при перетаскивании слова над ней (визуальный индикатор — горизонтальная линия места вставки).
- **FR-008**: Система MUST обеспечивать у gap-зон достаточную область наведения для комфортного попадания курсором.
- **FR-009**: Система MUST применять изменения раскладки только в локальном состоянии до явного действия «Сохранить порядок»; серверная раскладка MUST NOT изменяться автоматически при drop.
- **FR-010**: Система MUST отображать статусы и сообщения, связанные с сохранением порядка, на русском языке в стиле существующего редактора.
- **FR-011**: Система MUST NOT требовать изменений серверного API или формата сохранения раскладки; существующая операция сохранения порядка MUST принимать раскладку с произвольным числом строк, включая строки с одним словом.

### Key Entities

- **Локальная раскладка (layout)**: двумерный упорядоченный список строк, каждая строка — упорядоченный список слов; может расходиться с сохранёнными данными до «Сохранить порядок».
- **Слово**: элемент раскладки с текстом, идентификатором и метаданными; участвует в перетаскивании.
- **Gap-зона**: логическая область между строками (или перед первой / после последней), предназначенная для создания новой строки при drop.
- **Индикатор drop-цели**: визуальная подсветка активной gap-зоны во время перетаскивания.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Оператор может перенести слово на новую строку в начале, между строками или в конце документа не более чем за одно перетаскивание; успешный перенос подтверждается визуально без перезагрузки страницы.
- **SC-002**: 100% регрессионных сценариев (drop на слово, drop на строку, сохранение порядка, отмена) проходят проверку на том же наборе тестовых раскладок, что использовались до фичи.
- **SC-003**: Не менее 90% пробных drop в gap-зоны с первой попытки попадают в intended зону при обычном использовании мышью (достаточная hit-area).
- **SC-004**: При drag-over оператор различает активную gap-зону от остального текста за счёт видимой горизонтальной подсветки в течение всего времени нахождения курсора над зоной.
- **SC-005**: После сохранения порядка раскладка с новыми строками корректно отображается при повторном открытии скана (строки и порядок слов совпадают с сохранённым).

## Assumptions

- Целевые пользователи — операторы, правящие порядок распознанных слов на существующем экране скана; отдельный мобильный или touch-only UX вне scope.
- Backend и контракт `PUT …/words/layout` ({ lines: массив массивов id слов }) уже поддерживают произвольное число строк; изменения только на стороне клиента.
- Существующий механизм drag-and-drop в текстовом блоке расширяется, а не заменяется.
- Пустые строки в локальной раскладке не отображаются оператору (строка без слов не показывается).
- Визуальный стиль подсветки gap согласуется с уже используемой подсветкой drop-цели для слов в том же блоке.
- Сообщения «Сохранение порядка», «Порядок сохранён», «Порядок не менялся», «Сначала сохраните новое слово» и формат ошибок остаются без изменения текста, если не требуется новое сообщение для gap-сценариев.

## Out of Scope

- Изменения серверного API, схемы БД и бизнес-логики сохранения раскладки.
- Drag-and-drop вне текстового блока recognized-text (например, на изображении скана).
- Автосохранение порядка при drop; объединение или разбиение строк без явного перетаскивания.
- Клавиатурная навигация и альтернативные способы создания новой строки без мыши.
