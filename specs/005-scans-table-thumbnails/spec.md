# Feature Specification: Таблица сканов с пагинацией и миниатюрами

**Feature Branch**: `005-scans-table-thumbnails`

**Created**: 2026-08-14

**Status**: Draft

**Input**: User description: "Добавить отображение таблицы всех сканов, хранящихся в БД, с пагинацией и облегчёнными миниатюрами. Backend: GET /api/Scans?page={page} — страница сканов (только { id }) и общее количество, размер страницы 30, сортировка по id убыванию, page=1. GET /api/scans/{id}/thumbnail — уменьшенная версия (~200px) на лету без сохранения на диск, Cache-Control, ошибки как у векторизации. Frontend: таблица с миниатюрами, пагинация вперёд/назад по total, клик по строке открывает скан в редакторе как при upload. Вне объёма: настраиваемый размер страницы, хранение миниатюр, дата загрузки, число слов, удаление, поиск/фильтрация."

## Clarifications

### Session 2026-08-14

- Q: При клике по строке таблицы нужно ли подгружать уже сохранённые слова этого скана в редактор, или открывать его строго как после загрузки файла — только изображение, без слов? → A: Сброс редактора, затем загрузить уже сохранённые слова скана; если слов нет — список слов пуст (вариант B). Распознавание при открытии не запускать.
- Q: Если оператор загружает новый файл, находясь не на первой странице таблицы, куда должна перейти таблица после успешной загрузки? → A: После успешной загрузки перейти на первую страницу и обновить список — новый скан виден сразу (вариант A).
- Q: Если запрос страницы списка сканов не удался (сеть или ошибка сервера), что должен увидеть оператор? → A: Показать текстовую ошибку; если страница уже была на экране — оставить её, не затирать (вариант B).
- Q: Нужно ли в таблице визуально отмечать строку скана, который сейчас открыт в редакторе? → A: Да: строка текущего скана выделена, если он есть на текущей странице (вариант A).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Просмотр таблицы всех сканов с миниатюрами (Priority: P1)

Оператор открывает приложение и видит таблицу сканов, уже сохранённых в системе. Каждая строка показывает идентификатор скана и уменьшенную картинку документа, а не полноразмерное изображение. Сканы идут от новых к старым. На одной странице таблицы не больше 30 строк.

**Why this priority**: Без списка оператор не может найти уже загруженные документы и вынужден заново загружать файл, даже если скан уже есть в системе. Это основная ценность фичи.

**Independent Test**: Загрузить несколько сканов, открыть экран: таблица показывает их с миниатюрами, новые сверху, не более 30 строк на первой странице.

**Acceptance Scenarios**:

1. **Given** в системе есть сохранённые сканы, **When** оператор открывает основной экран, **Then** видна таблица сканов: у каждой строки есть идентификатор и миниатюра, порядок — от большего идентификатора к меньшему.
2. **Given** в системе больше 30 сканов, **When** отображается первая страница, **Then** в таблице не более 30 строк, при этом оператор понимает, что есть следующие страницы.
3. **Given** таблица отображает строки, **When** браузер запрашивает картинки для ячеек, **Then** используются облегчённые миниатюры, а не полноразмерные изображения сканов.
4. **Given** оператор находится не на первой странице таблицы, **When** загрузка нового файла успешно завершена, **Then** таблица показывает первую страницу, и новый скан виден в списке (сверху, как самый новый).

---

### User Story 2 - Переход по страницам списка (Priority: P1)

Оператор листает список вперёд и назад. Система опирается на общее число сканов, чтобы знать, какая страница последняя: на первой нельзя уйти «назад», на последней — «вперёд». Если на последней странице сканов меньше 30, показываются только они.

**Why this priority**: Без пагинации список всех сканов не масштабируется; фиксированный размер страницы — часть заявленного контракта.

**Independent Test**: Имея больше 30 сканов, пройти с первой страницы на следующую и вернуться; на последней странице кнопка «вперёд» недоступна.

**Acceptance Scenarios**:

1. **Given** оператор на первой странице и всего сканов больше размера страницы, **When** он нажимает «вперёд», **Then** показывается следующая порция сканов без пропуска и без дублирования строк текущей страницы.
2. **Given** оператор не на первой странице, **When** он нажимает «назад», **Then** возвращается предыдущая страница того же размера (кроме последней, которая может быть короче).
3. **Given** известно общее число сканов, **When** оператор находится на последней странице, **Then** переход вперёд недоступен; на первой странице недоступен переход назад.
4. **Given** в системе нет сканов, **When** открыт список, **Then** таблица пуста, пагинация не уводит на несуществующие страницы.
5. **Given** страница таблицы уже показана, **When** повторный запрос списка завершается ошибкой, **Then** оператор видит текстовое сообщение, а ранее показанные строки и номер страницы не затираются пустым списком.
6. **Given** список ещё ни разу не загрузился успешно, **When** запрос страницы завершается ошибкой, **Then** оператор видит текстовое сообщение, таблица без строк (подставлять выдуманные сканы нельзя).

### User Story 3 - Открытие скана из таблицы в редакторе (Priority: P1)

Оператор выбирает строку таблицы. Состояние работы с предыдущим сканом сбрасывается так же, как при выборе нового файла для загрузки; выбранный документ становится текущим, показывается его изображение. Затем клиент загружает уже сохранённые слова этого скана (существующее чтение списка слов). Если слов нет — список слов пуст, как сразу после загрузки до распознавания; распознавание при открытии из таблицы не запускается. Строка текущего скана в таблице визуально выделена, если этот скан есть на открытой странице.

**Why this priority**: Таблица бесполезна, если из неё нельзя продолжить работу с уже сохранённым документом.

**Independent Test**: Открыть скан A в редакторе (с словами/черновиком), затем кликнуть в таблице по скану B; редактор показывает B без остатков состояния A.

**Acceptance Scenarios**:

1. **Given** в редакторе открыт один скан с распознанными словами и/или черновиком правки, **When** оператор кликает по другой строке таблицы, **Then** текущим становится выбранный скан, изображение меняется на его файл, следы предыдущего скана (слова, раскладка, черновик, статусы операций) не сохраняются.
2. **Given** выбранный из таблицы скан уже имеет сохранённые слова, **When** редактор открыт, **Then** оператор видит эти слова и может продолжить работу без повторной загрузки файла.
3. **Given** выбранный скан не имеет слов, **When** редактор открыт, **Then** изображение скана доступно, список слов пуст — как после новой загрузки до распознавания.
4. **Given** оператор кликает по строке уже открытого скана, **When** выбор повторён, **Then** редактор остаётся на этом скане без «утечки» чужого состояния; повторный сброс допустим и не ломает экран.
5. **Given** скан открыт в редакторе и его строка есть на текущей странице таблицы, **When** оператор смотрит на таблицу, **Then** эта строка визуально отличается от остальных.
6. **Given** открыт скан, которого нет на текущей странице таблицы, **When** оператор листает список, **Then** ни одна строка не выглядит как «текущая», пока страница с этим сканом снова не открыта.

### User Story 4 - Предсказуемые ошибки миниатюр без поломки таблицы (Priority: P2)

Если у отдельного скана нет файла на диске или изображение повреждено, строка таблицы всё равно видна (идентификатор остаётся). В ячейке миниатюры — пустое/замещающее состояние, а не падение всего списка. Сообщения об отсутствии файла совпадают с уже принятыми в проекте формулировками для выдачи изображения и векторизации.

**Why this priority**: Повреждённые записи не должны скрывать остальные сканы; диагностика следует уже знакомой карте ошибок.

**Independent Test**: Имитировать отсутствующий файл у одного скана на странице; таблица и остальные миниатюры остаются рабочими.

**Acceptance Scenarios**:

1. **Given** запись скана есть, а файл на диске отсутствует, **When** запрашивается миниатюра, **Then** система отвечает «не найдено» с текстом «Не найден файл»; строка таблицы не пропадает.
2. **Given** файл есть, но содержимое повреждено и не читается как изображение, **When** запрашивается миниатюра, **Then** система отвечает ошибкой клиента с текстовым пояснением на русском; остальные строки таблицы отображаются как обычно.
3. **Given** записи скана с указанным идентификатором нет, **When** запрашивается миниатюра, **Then** система отвечает «не найдено» с текстом в том же духе, что при запросе полноразмерного изображения (запись в хранилище не найдена).

---

### Edge Cases

- Пустая база: таблица без строк; общее количество 0; кнопки пагинации не ведут на page < 1.
- Последняя страница короче 30 строк (остаток от деления общего числа на размер страницы).
- Запрос страницы с номером меньше 1: ошибка валидации входа (400) с текстовым сообщением на русском.
- Запрос страницы дальше последней: успешный ответ с пустым списком строк и тем же общим количеством (клиент не «ломается», просто нет строк).
- Пропуск параметра страницы: трактуется как первая страница (page = 1).
- Миниатюра для несуществующего id: 404, таблица других сканов не затрагивается.
- После успешной загрузки нового скана клиент переключает таблицу на первую страницу и заново запрашивает список; новый скан виден сразу (сверху при сортировке по убыванию id), даже если до загрузки была открыта другая страница.
- Одновременный просмотр таблицы и редактора: пагинация таблицы не сбрасывает открытый скан, пока оператор не кликнет другую строку.
- Выделение строки: только если `id` текущего скана редактора совпадает со строкой на открытой странице; на других страницах выделения нет. После успешной загрузки нового файла выделен новый скан на первой странице. Если текущий скан ещё не выбран — ни одна строка не выделена.
- Сбой запроса списка (сеть или ошибка сервера): текстовое сообщение на русском; если строки уже были на экране — они остаются; если успешной загрузки ещё не было — таблица пустая, без ложных строк.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система MUST отдавать постраничный список сканов по запросу `GET /api/Scans?page={page}`. Первая страница — `page=1`. Размер страницы MUST быть фиксированной серверной константой, равной 30; клиент MUST NOT выбирать размер страницы.
- **FR-002**: Элемент списка MUST содержать только идентификатор скана (`id`). Тело успешного ответа MUST включать массив элементов текущей страницы и общее количество сканов в хранилище (поле общего количества — `totalCount`, массив — `items`).
- **FR-003**: Сортировка списка MUST быть по идентификатору по убыванию (новые сканы сверху).
- **FR-004**: При `page` меньше 1 система MUST вернуть 400 с текстовым телом на русском. При отсутствии `page` система MUST отдать первую страницу. При `page` больше последней система MUST вернуть 200 с пустым `items` и корректным `totalCount`.
- **FR-005**: Система MUST отдавать уменьшенную копию изображения скана по запросу `GET /api/Scans/{id}/thumbnail`. Большая сторона миниатюры MUST быть около 200 пикселей (пропорции исходного кадра сохраняются). Миниатюра MUST формироваться на лету из исходного файла и MUST NOT сохраняться на диск.
- **FR-006**: Успешный ответ миниатюры MUST содержать заголовок, разрешающий кэширование изображения браузером (`Cache-Control`).
- **FR-007**: Если запись скана не найдена, запрос миниатюры MUST вернуть 404 с текстовым телом «Не найдена запись в БД» (тот же смысл, что у выдачи полноразмерного изображения). Если файл отсутствует — 404 с телом «Не найден файл». Если содержимое повреждено и не читается как изображение — 400 с текстовым пояснением на русском. Тела ошибок MUST быть plain text, не JSON ProblemDetails.
- **FR-008**: Клиент MUST показывать таблицу всех сканов на основном экране: колонки — миниатюра и идентификатор. Источник миниатюры — thumbnail-запрос из FR-005, MUST NOT быть полноразмерное изображение скана.
- **FR-009**: Клиент MUST предоставлять переход на соседние страницы (вперёд и назад). Номер последней страницы MUST вычисляться из `totalCount` и фиксированного размера 30. На первой странице «назад» недоступен; на последней — «вперёд».
- **FR-010**: По клику на строку таблицы клиент MUST сделать выбранный скан текущим в существующем редакторе и сбросить состояние редактора так же, как при выборе нового файла для загрузки (слова, раскладка, черновик, статусы операций предыдущего скана не переносятся).
- **FR-011**: После сброса при открытии скана из таблицы клиент MUST загрузить уже сохранённые слова этого скана существующим чтением списка слов; если слов нет, редактор остаётся пустым по словам, как после загрузки до распознавания. Распознавание MUST NOT запускаться автоматически при открытии из таблицы. Изображение редактора берётся из уже существующей выдачи полноразмерного файла, не из миниатюры.
- **FR-012**: После успешной загрузки нового файла клиент MUST переключить таблицу на первую страницу (`page=1`) и повторно запросить список, чтобы новый скан был виден без ручного листания назад.
- **FR-013**: Если запрос страницы списка не удался, клиент MUST показать понятное текстовое сообщение (тело ошибки сервера или сообщение о сети, на русском). Уже отображённые строки и текущий номер страницы MUST NOT затираться пустым списком. Если успешного ответа ещё не было, таблица MUST остаться без строк.
- **FR-014**: Клиент MUST визуально выделять строку таблицы, соответствующую скану, открытому в редакторе, если этот скан присутствует на текущей странице. Строки других сканов MUST NOT выглядеть выделенными. Если текущий скан на странице отсутствует или скан ещё не выбран, выделение MUST отсутствовать.
- **FR-015**: Фича MUST NOT включать: настраиваемый размер страницы; предвычисление и хранение миниатюр; колонку даты загрузки; колонку числа слов; удаление скана; поиск и фильтрацию списка.

### Key Entities

- **Скан**: Сохранённый документ (запись + файл изображения). В списке идентифицируется только `id`; содержимое файла нужно для миниатюры и для редактора.
- **Страница списка сканов**: Порция до 30 сканов плюс общее количество записей; нужна клиенту, чтобы показать таблицу и границы пагинации.
- **Миниатюра скана**: Облегчённая уменьшенная копия изображения (большая сторона ~200px), строится по требованию и не хранится отдельно.
- **Редактор скана**: Существующий основной экран работы с выбранным документом (изображение, слова, раскладка); открывается из таблицы тем же сбросом контекста, что при загрузке файла.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Оператор видит первую страницу списка сканов (миниатюра + идентификатор) без ручного ввода идентификатора и без повторной загрузки файла.
- **SC-002**: На любой странице в таблице не больше 30 строк; при общем числе сканов N оператор может последовательно пройти все страницы и увидеть каждый скан ровно один раз за полный проход.
- **SC-003**: В 100% случаев, когда общее число сканов известно, кнопки «назад»/«вперёд» соответствуют первой и последней странице (нельзя уйти за границы списка).
- **SC-004**: Открытие скана из таблицы занимает не более одного действия (клик по строке); после этого редактор показывает выбранный документ, а не предыдущий, а строка этого скана на текущей странице таблицы визуально выделена.
- **SC-005**: Миниатюры в таблице визуально соответствуют документам и заметно легче полноразмерных изображений: большая сторона кадра миниатюры около 200 пикселей.
- **SC-006**: В 100% негативных сценариев миниатюры (нет записи, нет файла, повреждённое изображение) оператор по-прежнему видит остальные строки списка; сообщение об отсутствии файла совпадает с уже принятой формулировкой «Не найден файл».
- **SC-007**: Не менее 90% участников короткой проверки подтверждают, что могут найти недавно загруженный скан на первой странице и открыть его в редакторе без повторной загрузки файла.
- **SC-008**: В 100% сбоев загрузки списка оператор видит текстовое сообщение; уже показанная страница в 100% таких случаев не заменяется пустой таблицей.

## Assumptions

- Маршруты следуют существующему контроллеру сканов: список — `GET /api/Scans`, миниатюра — `GET /api/Scans/{id}/thumbnail` (регистр пути для клиента несущественен).
- Форма JSON списка: `{ "items": [ { "id": <number> } ], "totalCount": <number> }` — разумный контракт под формулировку «страница сканов (только id) и общее количество».
- Размер страницы 30 задаётся в серверной секции Options (`ScanList`), по аналогии с `WordVectorization`; клиент размер страницы не передаёт и не выбирает.
- Миниатюра строится уже имеющимся в проекте средством обработки изображений, без новых внешних сервисов и без записи файла миниатюры в каталог хранения сканов.
- Значение `Cache-Control` для миниатюры — долгосрочное кэширование браузером (файл скана по записи не перезаписывается); точный `max-age` выбирается на этапе планирования.
- Карта ошибок миниатюры совпадает с выдачей изображения и векторизацией: нет записи → 404 «Не найдена запись в БД»; нет файла → 404 «Не найден файл»; повреждённое содержимое → 400 с русским текстом.
- Сброс редактора при клике по строке копирует набор сбрасываемых полей из сценария выбора файла для загрузки; затем клиент читает сохранённые слова выбранного скана. Повторное распознавание при открытии не выполняется.
- Таблица размещается на том же основном экране, что и редактор, и доступна постоянно (не отдельный «режим»).
- Способ выделения строки (фон, рамка, жирный идентификатор и т.п.) выбирается на этапе реализации при условии однозначной отличимости от невыделенных строк.
- После успешной загрузки нового файла таблица всегда показывает первую страницу с обновлённым списком; оставаться на прежнем номере страницы нельзя.
- Схема данных не меняется: используются существующие записи сканов.
- Вне объёма, явно: настраиваемый размер страницы; хранение миниатюр на диске; дата загрузки; число слов на скан; удаление скана; поиск и фильтрация.
