# Contract: UI — таблица сканов

**Feature**: `005-scans-table-thumbnails`  
**Date**: 2026-08-14

Клиент потребляет [scans-list.md](./scans-list.md) и [scan-thumbnail.md](./scan-thumbnail.md). Редактор по-прежнему использует существующие `GET …/image` и `GET …/words`.

## Размещение

Секция таблицы на основном экране (`App.tsx`), постоянно видима (не отдельный route). Рядом с загрузкой файла и редактором.

## Таблица

| Колонка | Источник |
|---------|----------|
| Миниатюра | `<img src="/api/Scans/{id}/thumbnail">` — **не** `/image` |
| Идентификатор | `items[].id` |

- Строка кликабельна → открытие скана (ниже)
- `item.id === scanId` → CSS-класс текущей строки (напр. `.current`); иначе без выделения
- `onError` у миниатюры: пустая/замещающая ячейка, строка не удаляется

## Пагинация

- Клиентская константа `SCAN_PAGE_SIZE = 30` (совпадает с `ScanList:PageSize`)
- `lastPage = max(1, ceil(totalCount / SCAN_PAGE_SIZE))`
- Кнопки «Назад» / «Вперёд»; disabled на стр. 1 / последней
- Смена страницы **не** сбрасывает `scanId` редактора

## Загрузка списка и ошибки

| Событие | Поведение |
|---------|-----------|
| Mount / смена `listPage` | `GET /api/Scans?page=` |
| `!ok` или сеть | `response.text()` / сообщение сети → статус RU; **не** затирать уже показанные `items` |
| Первый запрос ещё не успел | таблица без строк + сообщение |
| Успешный upload | `listPage = 1`, повторный GET page=1 |

## Открытие строки

Общий сброс редактора с `handleFileChange` (words, layout, draft, статусы, imageSize, drag, vectorize/delete). Затем:

1. `setScanId(id)`
2. `fetchWords(id)` → слова + `syncLayoutFromWords`
3. Recognize **не** вызывать
4. `<img>` редактора: существующий `/api/scans/{id}/image`

Ошибка GET words: текстовое сообщение; данные прежнего скана не возвращаются (уже сброшены).

## Вне scope UI

Настраиваемый размер страницы, дата, число слов, удаление скана, поиск/фильтр.
