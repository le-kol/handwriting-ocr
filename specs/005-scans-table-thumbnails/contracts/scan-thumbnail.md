# Contract: GET scan thumbnail

**Feature**: `005-scans-table-thumbnails`  
**Date**: 2026-08-14

## Endpoint

```http
GET /api/Scans/{id}/thumbnail
```

| Parameter | In | Type | Description |
|-----------|----|------|-------------|
| `id` | path | int | Id скана |

**Body**: none.

**Content-Type ответа (успех)**: `image/png` или `image/jpeg` (как у исходного файла, по расширению пути — тот же смысл, что `GET …/image`)  
**Content-Type ответа (ошибка)**: `text/plain` (строка на русском), без ProblemDetails.

## Success

**200 OK** — тело: байты уменьшенного изображения.

Инварианты:

- большая сторона кадра ≈ 200px (не больше; мелкие исходники не увеличиваются)
- пропорции исходного кадра сохранены
- файл миниатюры на диск **не** пишется
- заголовок: `Cache-Control: public, max-age=86400`

Не использовать этот URL как источник изображения **редактора** (там остаётся `GET /api/Scans/{id}/image`).

## Error responses

| Status | Когда | Пример тела |
|--------|-------|-------------|
| 404 | Скан не найден в БД | `Не найдена запись в БД` |
| 404 | Файл отсутствует на диске | `Не найден файл` |
| 400 | Повреждённое / нечитаемое содержимое | `Повреждённое или нечитаемое изображение скана.` |

Маппинг — как у векторизации / `GetImage`: `ResourceNotFoundException` → 404, `ArgumentException` → 400.

## Out of scope

- Предвычисление и хранение миниатюр
- Настраиваемый размер стороны клиентом
- Полноразмерный `/image` в ячейках таблицы
