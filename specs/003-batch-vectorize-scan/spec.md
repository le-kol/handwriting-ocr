# Feature Specification: Пакетная векторизация слов скана

**Feature Branch**: `003-batch-vectorize-scan`

**Created**: 2026-08-12

**Status**: Draft

**Input**: User description: "Добавить endpoint пакетной векторизации всех невекторизованных слов скана: POST /api/Scans/{id}/vectorize-batch. Выполняет векторизацию для всех слов скана с curve_points IS NULL, вызывая существующую логику одиночной векторизации независимо для каждого. Неудача одного слова не прерывает обработку остальных. Ответ при успешном выполнении запроса (скан найден, конфигурация валидна) — 200 OK, тело — актуальный список всех слов скана в том же формате, что у GET /api/Scans/{id}/words (включая curvePoints: массив для успешно векторизованных, null для слов без вектора — как до вызова, так и при неудаче текущей попытки). Причина неудачи конкретного слова в ответе batch не возвращается; для диагностики конкретного слова используется существующий одиночный endpoint POST .../words/{wordId}/vectorize. Top-level ошибки (скан не найден, невалидна конфигурация WordVectorization) — по существующей карте конституции (404/503, plain text). Слова, уже имеющие curve_points, повторно batch не обрабатывает."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Пакетная векторизация всех невекторизованных слов скана (Priority: P1)

Оператор (или вызывающая система) запрашивает пакетную векторизацию для выбранного скана одним действием. Система находит скан, определяет все слова без сохранённого векторного представления и для каждого из них выполняет ту же векторизацию, что и при одиночном запросе по слову. Успешно обработанные слова получают сохранённое представление; слова, для которых векторизация не удалась, остаются без представления. По завершении оператор получает полный актуальный список всех слов скана и видит, какие из них теперь векторизованы.

**Why this priority**: Это основная ценность фичи — массовая обработка без ручного вызова векторизации для каждого слова.

**Independent Test**: На скане с несколькими словами без векторного представления вызвать пакетную векторизацию; убедиться, что успешно обработанные слова имеют представление, а ответ содержит полный список слов скана.

**Acceptance Scenarios**:

1. **Given** скан существует и содержит слова без векторного представления, **When** запрошена пакетная векторизация, **Then** система обрабатывает каждое такое слово и возвращает 200 с полным списком всех слов скана в том же формате, что при чтении списка слов скана.
2. **Given** часть слов успешно векторизуется, а часть завершается неудачей, **When** пакетная векторизация завершена, **Then** система возвращает 200, успешные слова содержат векторное представление, неудачные остаются без него, обработка не прерывается из-за отдельных неудач.
3. **Given** пакетная векторизация завершена успешно на уровне запроса, **When** оператор просматривает ответ, **Then** у каждого слова поле векторного представления либо массив кривых (если вектор есть), либо отсутствует/null (если вектора нет).

---

### User Story 2 - Пропуск уже векторизованных слов (Priority: P1)

Оператор повторно запускает пакетную векторизацию на скане, где часть слов уже имеет сохранённое представление. Система не перезаписывает и не повторно обрабатывает слова с уже сохранённым представлением; обрабатывает только слова без представления.

**Why this priority**: Повторный запуск должен быть безопасным и идемпотентным по отношению к уже обработанным словам; иначе массовая операция рискует лишней нагрузкой и неожиданной заменой данных.

**Independent Test**: Векторизовать один слово одиночным запросом, затем вызвать пакетную векторизацию; убедиться, что ранее векторизованное слово не изменилось и не обрабатывалось повторно.

**Acceptance Scenarios**:

1. **Given** у части слов скана уже есть сохранённое векторное представление, **When** запрошена пакетная векторизация, **Then** слова с существующим представлением не включаются в обработку и сохраняют прежнее представление без изменений.
2. **Given** все слова скана уже векторизованы, **When** запрошена пакетная векторизация, **Then** система возвращает 200 с полным списком слов без изменения их представлений.

---

### User Story 3 - Предсказуемые ошибки уровня запроса (Priority: P1)

При невозможности начать пакетную обработку из-за отсутствия скана или невалидной конфигурации векторизации система сообщает об ошибке понятным текстом и не возвращает частичный список слов как успешный результат операции.

**Why this priority**: Ошибки конфигурации и отсутствия скана должны быть явными до начала массовой обработки; иначе вызывающая сторона не сможет отличить полный сбой от частичного успеха.

**Independent Test**: Запросить пакетную векторизацию для несуществующего скана и при отключённой/невалидной конфигурации векторизации; проверить коды и текстовые сообщения ошибок.

**Acceptance Scenarios**:

1. **Given** скан с указанным идентификатором не существует, **When** запрошена пакетная векторизация, **Then** система возвращает ошибку «не найдено» (404) с текстовым сообщением, без изменений данных слов.
2. **Given** конфигурация параметров векторизации отсутствует или невалидна, **When** запрошена пакетная векторизация, **Then** система возвращает ошибку недоступности сервиса (503) с текстовым сообщением и не начинает обработку слов.

---

### User Story 4 - Диагностика неудачи отдельного слова через одиночный endpoint (Priority: P2)

После пакетной векторизации оператор видит, что у отдельного слова по-прежнему нет векторного представления, но в ответе пакетной операции причина не указана. Для выяснения причины оператор использует существующий одиночный запрос векторизации по этому слову, который возвращает понятную текстовую ошибку.

**Why this priority**: Пакетный ответ намеренно не перегружен деталями по каждому слову; диагностика остаётся на уже существующем контракте одиночной векторизации.

**Independent Test**: После batch, при котором одно слово осталось без вектора, вызвать одиночную векторизацию для этого слова и получить текст ошибки.

**Acceptance Scenarios**:

1. **Given** пакетная векторизация завершилась с 200, но у слова представление осталось отсутствующим, **When** оператор запрашивает одиночную векторизацию этого слова, **Then** система возвращает текстовую ошибку с причиной неудачи согласно существующему контракту одиночной векторизации.

---

### Edge Cases

- Скан без слов: запрос завершается 200 с пустым списком слов; обработка не требуется.
- Все слова уже векторизованы: 200, список слов без изменений представлений.
- Смешанный результат (часть успех, часть неудача): 200, в списке у успешных — представление, у неудачных — null/отсутствие; причины по словам в теле ответа не перечисляются.
- Недоступный или повреждённый файл скана, вырожденная рамка, отсутствие штрихов у отдельного слова: трактуются как неудача векторизации этого слова внутри batch; запрос в целом остаётся 200 при найденном скане и валидной конфигурации; представление слова не затирается частичным результатом.
- Повторный OCR скана, заменивший набор слов: новые слова без представления попадают в batch; старые векторы не наследуются (как в одиночной векторизации).
- Параллельные одиночные и пакетные запросы для одного скана: вне scope явной синхронизации; ожидается поведение, согласованное с одиночной векторизацией (без частичных записей представления).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система MUST принимать запрос пакетной векторизации скана по идентификатору скана в маршруте: `POST /api/Scans/{id}/vectorize-batch`. Тело запроса MUST NOT требоваться; параметры векторизации берутся из конфигурации приложения (как при одиночной векторизации).
- **FR-002**: Если скан с указанным идентификатором не найден, система MUST вернуть 404 с текстовым телом сообщения на русском (карта ошибок проекта).
- **FR-003**: Если конфигурация параметров векторизации (`WordVectorization`) отсутствует или невалидна, система MUST вернуть 503 с текстовым телом сообщения на русском и MUST NOT начинать обработку слов.
- **FR-004**: При успешной валидации запроса (скан найден, конфигурация валидна) система MUST вернуть 200 OK.
- **FR-005**: Тело успешного ответа MUST быть полным списком всех слов указанного скана в том же формате элементов, что возвращает чтение списка слов скана (включая текст, рамку, порядок, строку и поле векторного представления `curvePoints`).
- **FR-006**: Система MUST определять к обработке только слова скана, у которых векторное представление отсутствует (`curve_points` IS NULL). Слова с уже сохранённым представлением MUST NOT обрабатываться повторно в рамках batch.
- **FR-007**: Для каждого слова, подлежащего обработке, система MUST выполнять ту же логику векторизации, что и при одиночном запросе векторизации слова (извлечение фрагмента, аппроксимация кривыми, сохранение при успехе).
- **FR-008**: Неудача векторизации одного слова MUST NOT прерывать обработку остальных слов в том же batch-запросе.
- **FR-009**: При неудаче векторизации конкретного слова в batch система MUST NOT сохранять частичное или пустое представление у этого слова; значение представления MUST оставаться отсутствующим, как до попытки.
- **FR-010**: Успешно векторизованные в batch слова MUST получать сохранённое представление; в ответе у таких слов `curvePoints` MUST быть непустым массивом кривых (тот же контракт, что у одиночной успешной векторизации).
- **FR-011**: Слова без представления (до batch, после неудачи в batch или не попавшие в обработку) MUST в ответе иметь `curvePoints: null` или эквивалентное отсутствие представления — в том же виде, что при чтении списка слов скана.
- **FR-012**: Ответ batch MUST NOT содержать причин неудачи или кодов ошибок по отдельным словам; диагностика конкретного слова MUST выполняться через существующий одиночный endpoint векторизации слова.
- **FR-013**: Тела ошибок уровня запроса MUST быть plain text на русском, без JSON ProblemDetails (принцип III конституции).
- **FR-014**: Фича MUST NOT требовать изменения схемы данных: используется существующая nullable-колонка векторного представления у слова.
- **FR-015**: Отдельный UI для запуска batch-векторизации MUST NOT входить в обязательный объём фичи; контракт — серверный endpoint, совместимый с существующими путями API сканов.

### Key Entities

- **Скан (Scan)**: Владелец набора слов и файла изображения; цель пакетного запроса — обработать все невекторизованные слова одного скана.
- **Слово (Word)**: Запись распознанного слова на скане с рамкой и опциональным векторным представлением штрихов. Критерий включения в batch — отсутствие сохранённого представления.
- **Векторное представление штрихов**: Набор кубических кривых Безье, сохранённый у слова; семантика и формат совпадают с одиночной векторизацией (фича `001-word-stroke-vector`).
- **Параметры векторизации**: Конфигурируемые значения отступа и погрешности; общие для одиночной и пакетной операций; невалидная конфигурация блокирует весь batch до обработки слов.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Оператор может одним запросом инициировать векторизацию всех невекторизованных слов скана и получить полный актуальный список слов без ручных повторных вызовов по каждому слову.
- **SC-002**: В 100% случаев, когда скан найден и конфигурация валидна, ответ batch имеет статус успеха (200), даже если часть слов не удалось векторизовать.
- **SC-003**: Слова с уже сохранённым представлением в 100% повторных batch-запросов остаются без повторной обработки и без неожиданной потери представления.
- **SC-004**: В 100% негативных сценариев уровня запроса (несуществующий скан, невалидная конфигурация) система возвращает соответствующую ошибку с текстовым сообщением и не выдаёт успешный список слов.
- **SC-005**: Для типичного скана с десятками слов время получения результата batch не превышает суммы времени одиночных векторизаций по тем же словам более чем на разумную накладную долю (последовательная обработка допустима; параллелизм не требуется).
- **SC-006**: После batch оператор может для любого слова без представления получить текстовую причину неудачи через одиночный endpoint векторизации.

## Assumptions

- Логика одиночной векторизации уже реализована и стабильна (фича `001-word-stroke-vector`); batch — оркестрация поверх неё, без изменения алгоритма аппроксимации.
- Обработка слов в batch выполняется последовательно или иным способом, не меняющим контракт ответа; порядок обработки в ответе не фиксируется.
- Пустой скан (0 слов) — валидный успешный случай с пустым массивом в теле ответа.
- Ошибки файла скана, рамки и отсутствия штрихов на уровне отдельного слова не повышают статус всего batch до 4xx/5xx; они отражаются только отсутствием `curvePoints` у соответствующего слова в успешном ответе.
- Клиентский UI для кнопки «Векторизовать все» может быть добавлен отдельно; в объём данной спецификации входит только серверный контракт.
- Формат списка слов и поля `curvePoints` идентичен уже существующему чтению слов скана и одиночной векторизации; новые поля в элементе списка не вводятся.
