# Feature Specification: Параметры запуска векторизации слов

**Feature Branch**: `011-vectorize-run-params`

**Created**: 2026-08-20

**Status**: Draft

**Input**: User description: "Дать оператору возможность перед запуском векторизации слова или пакетной векторизации всех слов скана указывать параметры этой операции — отступ вокруг рамки слова при вырезке фрагмента и допустимую погрешность аппроксимации формы штрихов кривыми — вместо того чтобы всегда использовать только серверные значения по умолчанию. Оператор должен видеть текущие действующие значения (заполненные значениями по умолчанию сервера при первом открытии) рядом с кнопками «Векторизовать» и «Векторизовать все слова» и иметь возможность изменить их перед запуском конкретной операции. Если оператор не меняет предложенные значения, результат и поведение операции должны быть полностью такими же, как до появления этой фичи. Если оператор указывает недопустимое значение (например, отрицательный отступ или нулевую/отрицательную погрешность), система должна отклонить запуск операции с понятным текстовым объяснением причины и не выполнять векторизацию, сохраняя прежнее состояние слов без изменений. Указанные оператором значения применяются только к конкретному запуску операции (одному слову или пакету слов скана) и не сохраняются как постоянное свойство слова, скана или конфигурации сервера — при следующем запуске снова предлагаются значения по умолчанию, если оператор явно не укажет свои. Функция ограничена только параметрами извлечения фрагмента и аппроксимации кривых для уже существующих операций векторизации (одиночной и пакетной). Настройка параметров распознавания текста (OCR) и любая предобработка изображения перед распознаванием — вне объёма и рассматриваются отдельной фичей. Изменение схемы базы данных, добавление новых сущностей или изменение того, что и как хранится в записи слова, не входит в объём — меняется только то, какие значения используются при вычислении векторного представления в момент запроса."

## Clarifications

### Session 2026-08-20

- Q: Поля отступа и погрешности должны быть двумя независимыми наборами (свои поля у каждой кнопки) или одним общим набором, который используется для той операции, что оператор запустит следующей? → A: Два независимых набора полей — свои у каждой кнопки («Векторизовать» и «Векторизовать все слова»); изменение значений одного набора не влияет на другой.
- Q: Если оператор одновременно вводит недопустимые значения и для отступа, и для погрешности, система должна показать одно сообщение с описанием всех найденных проблем сразу, или показать только первую найденную проблему? → A: Одно сообщение, перечисляющее все найденные проблемы одновременно (и по отступу, и по погрешности, если оба недопустимы).
- Q: Если действующие значения по умолчанию сервера недоступны или некорректны в момент отображения, что должен видеть оператор рядом с кнопками — поля и кнопки, или только текстовое сообщение об ошибке? → A: Показывается только текстовое сообщение об ошибке вместо полей значений и самой кнопки запуска операции.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Изменение параметров перед векторизацией одного слова (Priority: P1)

Оператор, работая с конкретным словом на скане, перед нажатием кнопки «Векторизовать» видит два предложенных значения — отступ вокруг рамки слова и допустимую погрешность аппроксимации кривых, — заполненные значениями по умолчанию сервера. Оператор изменяет одно или оба значения на нужные ему для этого конкретного слова и запускает векторизацию именно с этими значениями.

**Why this priority**: Это основная ценность фичи — без возможности реально задать другие значения для операции над одним словом остальная функциональность не имеет смысла. Одиночная векторизация — самый частый и контролируемый сценарий работы оператора.

**Independent Test**: Можно полностью протестировать, открыв слово, изменив предложенные значения отступа и погрешности на другие допустимые числа, запустив «Векторизовать» и убедившись, что результат векторизации слова получен с учётом изменённых значений (а не значений по умолчанию).

**Acceptance Scenarios**:

1. **Given** оператор впервые открыл панель работы со словом, **When** он видит поля значений рядом с кнопкой «Векторизовать», **Then** они уже заполнены действующими значениями по умолчанию сервера (отступ и допустимая погрешность).
2. **Given** поля показывают значения по умолчанию, **When** оператор меняет отступ и/или погрешность на другие допустимые значения и нажимает «Векторизовать», **Then** операция выполняется с указанными оператором значениями, а не со значениями по умолчанию.
3. **Given** оператор изменил значения и запустил векторизацию, **When** операция успешно завершается, **Then** результат для этого слова получен именно с использованием введённых оператором значений.

---

### User Story 2 - Изменение параметров перед пакетной векторизацией всех слов скана (Priority: P2)

Оператор, находясь на экране скана, перед нажатием кнопки «Векторизовать все слова» видит те же два предложенных значения — отступ и допустимую погрешность, — заполненные значениями по умолчанию сервера. Оператор изменяет их и запускает пакетную векторизацию: указанные значения применяются одинаково ко всем словам скана, обрабатываемым в рамках этого запуска.

**Why this priority**: Пакетная операция затрагивает сразу много слов, поэтому она ценна, но логически вторична по отношению к одиночной операции (P1), которая покрывает базовый механизм ввода и валидации параметров.

**Independent Test**: Можно полностью протестировать, открыв скан с несколькими невекторизованными словами, изменив предложенные значения отступа и погрешности рядом с кнопкой «Векторизовать все слова», запустив пакетную операцию и убедившись, что все обработанные слова получили результат, соответствующий изменённым значениям.

**Acceptance Scenarios**:

1. **Given** оператор открыл скан с невекторизованными словами, **When** он видит поля значений рядом с кнопкой «Векторизовать все слова», **Then** они заполнены действующими значениями по умолчанию сервера.
2. **Given** оператор изменил отступ и/или погрешность на другие допустимые значения, **When** он нажимает «Векторизовать все слова», **Then** все слова, обработанные в рамках этого запуска, векторизуются с использованием указанных оператором значений.

---

### User Story 3 - Отклонение недопустимых значений без изменения состояния слов (Priority: P2)

Оператор по ошибке вводит недопустимое значение (например, отрицательный отступ или нулевую/отрицательную погрешность) перед запуском одиночной или пакетной векторизации. Система не позволяет запустить операцию, показывает понятное текстовое объяснение причины отказа и не изменяет состояние слов (их прежний результат векторизации, если он был, остаётся прежним).

**Why this priority**: Без этой защиты оператор может случайно запустить операцию с бессмысленными параметрами или получить непонятную ошибку от сервера постфактум; корректная валидация — обязательное условие безопасного использования фичи, но она зависит от того, что поля ввода (US1/US2) уже существуют.

**Independent Test**: Можно полностью протестировать, введя отрицательный отступ (или нулевую/отрицательную погрешность) в поля рядом с любой из двух кнопок, нажав кнопку и убедившись, что: операция не выполняется, показывается понятное текстовое объяснение причины, а состояние слова(-ов) на скане не изменилось.

**Acceptance Scenarios**:

1. **Given** оператор ввёл отрицательное значение отступа, **When** он нажимает «Векторизовать» или «Векторизовать все слова», **Then** операция не запускается, показывается понятное текстовое объяснение («отступ не может быть отрицательным» или аналогичное), а состояние слов не меняется.
2. **Given** оператор ввёл нулевое или отрицательное значение допустимой погрешности, **When** он нажимает «Векторизовать» или «Векторизовать все слова», **Then** операция не запускается, показывается понятное текстовое объяснение, а состояние слов не меняется.
3. **Given** до попытки запуска слово уже имело результат векторизации, **When** запуск с недопустимым значением отклонён, **Then** ранее сохранённый результат векторизации этого слова остаётся без изменений.

---

### User Story 4 - Параметры не сохраняются между запусками (Priority: P3)

После того как оператор указал свои значения и запустил операцию (успешно или неуспешно), эти значения не становятся постоянным свойством слова, скана или серверной конфигурации. При следующем открытии слова/скана или следующем запуске операции оператору снова предлагаются значения по умолчанию сервера, если он явно не введёт свои заново.

**Why this priority**: Это важное ограничение, гарантирующее предсказуемость и отсутствие побочных эффектов, но оно наблюдаемо и проверяемо только после того, как основной механизм ввода и запуска (P1/P2) уже реализован.

**Independent Test**: Можно полностью протестировать, задав нестандартные значения для одной операции, затем перейдя к другому слову/скану или повторно открыв то же слово/скан, и убедившись, что поля снова показывают значения по умолчанию сервера, а не ранее введённые оператором значения.

**Acceptance Scenarios**:

1. **Given** оператор указал нестандартные значения и успешно запустил векторизацию слова, **When** он переходит к другому слову или повторно открывает то же слово, **Then** поля значений снова показывают значения по умолчанию сервера.
2. **Given** оператор указал нестандартные значения для пакетной векторизации одного скана, **When** он открывает другой скан или переоткрывает тот же скан, **Then** поля рядом с «Векторизовать все слова» снова показывают значения по умолчанию сервера.

---

### Edge Cases

- Что происходит, если оператор вводит в поле нечисловое значение или оставляет поле пустым? Система должна считать значение недопустимым и отклонить запуск с понятным текстовым объяснением — так же, как в случае отрицательного/нулевого значения.
- Что происходит, если значения по умолчанию сервера сами по себе недоступны или некорректны (например, серверная конфигурация не настроена)? Вместо полей значений и кнопки запуска соответствующей операции оператор должен увидеть только понятное текстовое сообщение об ошибке; запустить операцию в этом состоянии невозможно.
- Что происходит, если оператор вводит очень большое, но формально допустимое (неотрицательное/положительное) значение? Система принимает его как допустимое значение операции; если при таком значении фактическая обработка конкретного слова становится невозможной (например, вырожденная область вырезки), применяется то же поведение, что и сегодня при отказе обработки слова (отдельная ошибка для одиночной операции, пропуск слова без прерывания для пакетной).
- Что происходит, если оператор запускает пакетную векторизацию, изменив значения, пока уже выполняется одиночная векторизация другого слова (и наоборот)? Существующие ограничения на одновременный запуск операций векторизации не меняются этой фичей; какие значения используются, определяется тем, какая операция и с какими введёнными значениями была запущена.
- Что происходит, если оператор меняет значения, но не запускает операцию, а просто уходит с экрана слова/скана? Введённые, но не примененные к запуску значения не должны никак сохраняться и не должны влиять на последующие операции.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система MUST отображать рядом с кнопкой «Векторизовать» два редактируемых значения для предстоящей операции над словом: отступ вокруг рамки слова при вырезке фрагмента и допустимую погрешность аппроксимации формы штрихов кривыми.
- **FR-002**: Система MUST отображать рядом с кнопкой «Векторизовать все слова» те же два редактируемых значения для предстоящей пакетной операции над всеми словами скана.
- **FR-003**: При первом отображении этих значений (например, при открытии слова или скана) система MUST заполнять оба поля действующими значениями по умолчанию, определёнными серверной конфигурацией на момент отображения.
- **FR-004**: Оператор MUST иметь возможность изменить оба предложенных значения перед запуском конкретной операции (одиночной или пакетной). Поля значений для одиночной операции и поля значений для пакетной операции MUST быть двумя независимыми наборами — изменение значений в одном наборе MUST НЕ влиять на значения, отображаемые в другом.
- **FR-005**: Если оператор запускает операцию без изменения предложенных значений по умолчанию, итоговый результат и поведение операции MUST полностью совпадать с поведением, действовавшим до появления этой возможности (то есть быть эквивалентным использованию значений по умолчанию сервера напрямую).
- **FR-006**: Система MUST отклонять запуск операции (как одиночной, так и пакетной), если указанное оператором значение отступа отрицательное.
- **FR-007**: Система MUST отклонять запуск операции (как одиночной, так и пакетной), если указанное оператором значение допустимой погрешности аппроксимации равно нулю, отрицательно, отсутствует или не является числом.
- **FR-008**: При отклонении запуска из-за недопустимого значения система MUST показать оператору понятное текстовое объяснение причины отказа и MUST НЕ выполнять векторизацию. Если недопустимы одновременно и отступ, и допустимая погрешность, объяснение MUST описывать все найденные проблемы одновременно, а не только первую из них.
- **FR-009**: При отклонении запуска из-за недопустимого значения состояние слов, затронутых этим запуском (их существующий результат векторизации, если он был), MUST остаться без изменений.
- **FR-010**: Значения, указанные оператором для конкретного запуска операции, MUST применяться только к этому запуску (к одному указанному слову либо ко всем словам скана, обрабатываемым в рамках одного запуска пакетной операции) и MUST НЕ становиться постоянным свойством слова, скана или серверной конфигурации.
- **FR-011**: При пакетном запуске указанные оператором значения отступа и допустимой погрешности MUST применяться одинаково ко всем словам, обрабатываемым в рамках этого запуска.
- **FR-012**: После завершения операции (успешного или отклонённого) при следующем отображении полей значений (для того же или другого слова/скана) система MUST снова предлагать действующие значения по умолчанию сервера, если оператор явно не укажет свои значения для нового запуска.
- **FR-013**: Функция MUST ограничиваться только параметрами извлечения фрагмента слова (отступ) и аппроксимации кривых (допустимая погрешность) для уже существующих операций одиночной и пакетной векторизации; система MUST НЕ добавлять настройку параметров распознавания текста (OCR) или предобработки изображения перед распознаванием.
- **FR-014**: Функция MUST НЕ изменять то, какие данные и в каком виде сохраняются в записи слова, скана или конфигурации — меняется только то, какие значения используются при вычислении векторного представления в момент запроса конкретной операции.
- **FR-015**: Если действующие значения по умолчанию сервера недоступны или некорректны в момент отображения, система MUST вместо полей значений и кнопки запуска соответствующей операции («Векторизовать» или «Векторизовать все слова») показывать только понятное текстовое сообщение об ошибке и MUST НЕ позволять запустить эту операцию в таком состоянии.

### Key Entities *(include if feature involves data)*

- **Параметры запуска векторизации**: временный (не сохраняемый) набор из двух значений — отступ вокруг рамки слова и допустимая погрешность аппроксимации кривых, — существующий только в рамках одного запроса на одиночную или пакетную векторизацию. Не является атрибутом слова, скана или серверной конфигурации; после завершения запроса не сохраняется где-либо.
- **Значения по умолчанию векторизации**: действующие серверные значения отступа и допустимой погрешности, используемые для предзаполнения полей при отображении и как результат операции, если оператор их не изменил. Источник этих значений — существующая серверная конфигурация; их логическое существование не меняется этой фичей, но они впервые становятся видимыми и переопределяемыми оператором на конкретный запуск.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% запусков одиночной или пакетной векторизации без изменения предложенных значений дают результат, идентичный результату до появления этой фичи (при одинаковых входных данных слова/скана).
- **SC-002**: Оператор может увидеть действующие значения отступа и погрешности и изменить их перед запуском операции без обращения к разработчику или изменения серверной конфигурации.
- **SC-003**: 100% попыток запуска операции с недопустимым значением (отрицательный отступ; нулевая, отрицательная или нечисловая погрешность) отклоняются с понятным текстовым объяснением, и ни одно слово, затронутое такой попыткой, не меняет своего состояния.
- **SC-004**: После завершения операции с изменёнными оператором значениями следующий запуск (того же или другого слова/скана) предлагает значения по умолчанию, а не ранее введённые оператором значения — подтверждено в 100% проверок.

## Assumptions

- Отступ и допустимая погрешность отображаются и редактируются как числовые поля рядом с соответствующей кнопкой.
- Допустимые диапазоны значений соответствуют явно указанным в описании фичи ограничениям: отступ ≥ 0 (ноль допустим), допустимая погрешность строго больше 0. Верхняя граница значений не ограничивается этой фичей.
- Если серверные значения по умолчанию недоступны или некорректны на момент отображения, это считается тем же классом ситуации, что и сегодняшняя ошибка недоступности конфигурации векторизации: вместо полей значений и кнопки запуска оператор видит только текстовое сообщение об ошибке (см. FR-015).
- Пакетная операция продолжает применяться к тому же набору слов скана, что и сегодня (то есть к словам, ещё не имеющим результата векторизации); эта фича не меняет, какие слова участвуют в пакетном запуске — только какие значения отступа и погрешности используются при их обработке.
- Существующие ограничения на одновременный запуск операций векторизации (например, недопустимость одновременного запуска одиночной и пакетной операции) не входят в объём этой фичи и не меняются.
- Настройка параметров распознавания текста (OCR) и любая предобработка изображения перед распознаванием прямо исключены из объёма и не затрагиваются этой фичей.
- Изменение схемы базы данных, добавление новых сущностей или изменение состава/формата данных, хранимых в записи слова, скана или серверной конфигурации, не входит в объём — сохраняется только временное использование указанных оператором значений в момент вычисления результата конкретного запроса.
