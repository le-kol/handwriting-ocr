# Quickstart: Удаление скана

**Feature**: `006-delete-scan`  
**Date**: 2026-08-14

Ручная проверка end-to-end после реализации. Модель — [data-model.md](./data-model.md). HTTP — [contracts/delete-scan.md](./contracts/delete-scan.md). UI — [contracts/delete-scan-ui.md](./contracts/delete-scan-ui.md).

## Prerequisites

1. PostgreSQL доступна; FK `words → scans ON DELETE CASCADE` применён (без новых миграций).
2. Приложение запущено (`dotnet run --project handwritingOCR.Server`).
3. Есть хотя бы один скан с файлом на диске (`POST /api/Scans/upload`).
4. Для сценария пагинации — больше 30 сканов или удаление последнего на странице N > 1.

## Setup commands

```bash
dotnet run --project handwritingOCR.Server
```

Базовый URL API: `https://localhost:<port>/api`.

## Validation scenarios

### 1. DELETE существующего скана (P1)

```http
DELETE /api/Scans/{id}
```

**Ожидание**: `204`, без тела.  
`GET /api/Scans/{id}/image` → `404` «Не найдена запись в БД».  
`GET /api/Scans/{id}/words` → `404` «Не найдена запись в БД».  
Файл по прежнему `path` отсутствует на диске.  
Строки `words` с `scan_id = id` отсутствуют в БД.

SQL DELETE выполняется в `ScanDbService`, не в контроллере.

### 2. DELETE несуществующего id (P1)

```http
DELETE /api/Scans/999999
```

**Ожидание**: `404`, plain text `Не найдена запись в БД`.

### 3. DELETE при отсутствующем файле (P1)

Скан есть в БД, файл на диске удалён вручную.

```http
DELETE /api/Scans/{id}
```

**Ожидание**: `204`; запись в БД удалена; **не** `500`.

### 4. Удаление из редактора (P1)

Открыть скан, распознать слова, начать черновик правки. Нажать «Удалить скан».

**Ожидание**: один клик, без confirm; редактор пуст (`scanId` null, нет слов/рамок); повторное открытие того же id из таблицы невозможно (404 при загрузке).

### 5. Удаление из таблицы — другой скан открыт (P1)

Редактор на скане A. В таблице «Удалить» у скана B (B ≠ A).

**Ожидание**: B исчезает из списка после refresh; редактор по-прежнему показывает A.

### 6. Удаление из таблицы — текущий открытый (P1)

Редактор на скане A. «Удалить» в строке A.

**Ожидание**: A удалён; редактор сброшен как в сценарии 4; строка A пропала из таблицы.

### 7. Пустая страница после delete (P1)

На странице 2 ровно один скан. Удалить его из строки.

**Ожидание**: таблица показывает страницу 1 с актуальным списком, не пустую «страницу 2».

### 8. Ошибка удаления (P1)

Остановить API, нажать «Удалить».

**Ожидание**: текстовое сообщение об ошибке; скан остаётся в UI (строка и/или редактор).

### 9. Двойной клик (edge)

Быстро дважды «Удалить» по одной строке.

**Ожидание**: первый запрос — успех; второй — 404 с сообщением; UI не «ломается» (нет ложного пустого редактора без успеха первого запроса).

### 10. Клик «Удалить» не открывает скан (P1)

Клик по кнопке «Удалить» в строке (не по ячейке id/миниатюре).

**Ожидание**: не вызывается открытие строки; только удаление (после confirm отсутствует — сразу DELETE).

## Regression

- `GET /api/Scans?page=1` — без изменений ([005 quickstart](../../005-scans-table-thumbnails/quickstart.md)).
- `DELETE /api/Scans/{id}/words/{wordId}` — удаление слова по-прежнему работает.
- Upload, recognize, vectorize — без регрессий.

## Done when

- Все сценарии 1–10 пройдены в браузере и/или через HTTP-клиент.
