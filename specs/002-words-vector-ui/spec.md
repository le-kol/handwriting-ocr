# Feature Specification: Отображение и векторизация слов на клиенте

**Feature Branch**: `002-words-vector-ui`

**Created**: 2026-08-11

**Status**: Draft

**Input**: User description: "Добавить на фронтенде отображение слов из БД для выбранного скана в виде списка/таблицы, включая: текст слова, статус векторизации, и если слово векторизовано — миниатюру его векторного представления (рисуется из существующего поля curvePoints, полученного через GET /api/Scans/{id}/words). Векторное представление отображается отдельно от изображения скана, в собственной системе координат (bounding box кривых слова), не накладывается поверх скана — координаты curvePoints находятся в системе выровненного фрагмента слова и не соответствуют координатам скана напрямую. Дополнительно: кнопка «Векторизовать» рядом со словом, вызывающая существующий POST …/vectorize и обновляющая отображение слова после успешного ответа. Не входит в объём: наложение вектора поверх изображения скана в реальных координатах; batch-векторизация; редактирование вектора."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Просмотр слов выбранного скана со статусом векторизации (Priority: P1)

Оператор выбирает скан и видит список (или таблицу) слов этого скана. Для каждого слова показаны текст и статус векторизации (есть сохранённое векторное представление или нет). Если представление есть, рядом отображается миниатюра формы штрихов, нарисованная по сохранённым кривым слова.

**Why this priority**: Без просмотра слов и статуса оператор не может оценить результат векторизации и понять, какие слова уже обработаны.

**Independent Test**: Открыть скан, у которого часть слов уже векторизована, а часть — нет; убедиться, что список показывает текст, корректный статус и миниатюру только у векторизованных слов.

**Acceptance Scenarios**:

1. **Given** выбран скан с несколькими словами, **When** оператор просматривает список слов, **Then** для каждого слова отображаются текст и статус векторизации («векторизовано» / «не векторизовано» или эквивалентная явная индикация).
2. **Given** у слова есть сохранённое векторное представление, **When** список отображается, **Then** рядом со словом видна миниатюра, построенная по кривым этого слова.
3. **Given** у слова нет векторного представления, **When** список отображается, **Then** миниатюра не показывается (или явно пустое место без ложной геометрии), а статус указывает отсутствие векторизации.
4. **Given** выбран другой скан, **When** список обновляется, **Then** отображаются только слова нового скана (без остатков списка предыдущего).

---

### User Story 2 - Миниатюра вектора в собственной системе координат (Priority: P1)

Оператор смотрит на миниатюру векторизованного слова и видит форму штрихов в отдельной области, не наложенной на изображение скана. Миниатюра масштабируется по ограничивающему прямоугольнику кривых слова, чтобы форма была читаемой независимо от абсолютных размеров фрагмента.

**Why this priority**: Координаты кривых относятся к выровненному фрагменту слова и не совпадают с координатами скана; наложение на скан было бы неверным и вводит в заблуждение.

**Independent Test**: Сравнить миниатюру с ожидаемой формой штрихов слова; убедиться, что она не рисуется поверх изображения скана и умещается в собственной области превью.

**Acceptance Scenarios**:

1. **Given** у слова есть кривые с координатами в системе фрагмента, **When** рисуется миниатюра, **Then** она отображается в отдельной области списка/таблицы, а не поверх изображения скана.
2. **Given** кривые слова имеют произвольный диапазон координат в системе фрагмента, **When** рисуется миниатюра, **Then** видимая область строится по ограничивающему прямоугольнику этих кривых (с разумным запасом/масштабом), чтобы вся форма помещалась и была различима.
3. **Given** на экране одновременно видны изображение скана и список слов, **When** оператор сравнивает их, **Then** миниатюры слов не претендуют на совпадение с рамками/позициями на скане.

---

### User Story 3 - Векторизация слова по кнопке из списка (Priority: P1)

Оператор нажимает «Векторизовать» у конкретного слова. Система выполняет уже существующую серверную векторизацию этого слова и после успеха обновляет строку слова: статус становится «векторизовано», появляется (или обновляется) миниатюра.

**Why this priority**: Без запуска из UI оператор вынужден обходить API вручную; кнопка замыкает цикл «просмотр → действие → проверка результата».

**Independent Test**: На скане с невекторизованным словом нажать «Векторизовать»; после успеха увидеть обновлённый статус и миниатюру без полной перезагрузки приложения.

**Acceptance Scenarios**:

1. **Given** слово без векторного представления, **When** оператор нажимает «Векторизовать» и операция успешна, **Then** у этого слова обновляются статус и миниатюра по новому представлению.
2. **Given** слово уже векторизовано, **When** оператор снова нажимает «Векторизовать» и операция успешна, **Then** миниатюра отражает новое представление (замена прежнего), без появления дублирующей строки слова.
3. **Given** операция векторизации завершилась ошибкой, **When** ответ получен, **Then** оператор видит понятное текстовое сообщение об ошибке, а прежний статус и миниатюра слова (если были) не затираются ложными данными.
4. **Given** запрос векторизации ещё выполняется, **When** оператор смотрит на строку слова, **Then** повторный запуск для того же слова недоступен или явно блокируется, чтобы не слать параллельные дублирующие запросы.

---

### Edge Cases

- Скан без слов: список пуст с понятным состоянием («нет слов»), без ошибок интерфейса.
- Слова ещё загружаются: показывается состояние загрузки списка, а не пустой «успешный» список.
- У слова `curvePoints` отсутствует/`null`: статус «не векторизовано», миниатюра не рисуется.
- У слова некорректные/пустые данные кривых при заявленном наличии представления: миниатюра не ломает страницу; показывается статус/заглушка без падения UI.
- Очень большое число кривых или точек: миниатюра остаётся отзывчивой в пределах обычного списка слов скана (типичный рукописный скан).
- Ошибка сети или сервера при загрузке слов: понятное сообщение; список не показывает устаревшие слова другого скана как актуальные.
- Ошибка векторизации (слово не найдено, нет штрихов, файл скана недоступен и т.п.): текст ошибки показывается оператору; данные слова в списке сохраняют предыдущее корректное состояние.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: При выборе скана клиент MUST отображать список или таблицу слов этого скана, полученных из существующего источника данных слов скана.
- **FR-002**: Для каждого слова список MUST показывать текст слова.
- **FR-003**: Для каждого слова список MUST показывать статус векторизации на основе наличия сохранённого векторного представления (`curvePoints` присутствует и непустое → векторизовано; иначе → не векторизовано).
- **FR-004**: Если слово векторизовано, список MUST отображать миниатюру векторного представления, построенную по кубическим кривым Безье из `curvePoints` (каждая кривая — четыре контрольные точки с координатами x, y).
- **FR-005**: Миниатюра MUST отображаться в собственной системе координат (ограничивающий прямоугольник кривых слова), отдельно от изображения скана, и MUST NOT накладываться на изображение скана.
- **FR-006**: Миниатюра MUST NOT интерпретировать координаты кривых как координаты скана или рамки слова на скане.
- **FR-007**: Рядом с каждым словом MUST быть действие «Векторизовать», инициирующее существующую серверную векторизацию этого слова в контексте выбранного скана.
- **FR-008**: После успешной векторизации клиент MUST обновить отображение этого слова (статус и миниатюра) в соответствии с актуальными данными ответа или повторного чтения слов.
- **FR-009**: При ошибке векторизации клиент MUST показать оператору текстовое сообщение об ошибке и MUST NOT затирать ранее корректное векторное представление слова в UI.
- **FR-010**: Пока векторизация конкретного слова выполняется, клиент MUST предотвратить повторный параллельный запуск для того же слова (блокировка кнопки или эквивалент).
- **FR-011**: Фича MUST NOT включать: наложение вектора на изображение скана в «реальных» координатах скана; пакетную векторизацию нескольких слов одной кнопкой; редактирование контрольных точек/кривых вручную.

### Key Entities

- **Скан**: Выбранный документ; определяет набор слов для списка.
- **Слово**: Запись распознанного слова: текст, статус векторизации, опциональное векторное представление штрихов.
- **Векторное представление (`curvePoints`)**: Набор кубических кривых Безье в системе выровненного фрагмента слова; используется только для миниатюры в списке, не для позиционирования на скане.
- **Миниатюра вектора**: Визуальное превью формы штрихов слова в отдельной области списка, масштабированное по bounding box кривых.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: В 100% проверок на сканах с известным набором слов оператор видит полный список слов выбранного скана с текстом и корректным статусом векторизации без ручного обращения к API.
- **SC-002**: Для 100% слов с сохранённым векторным представлением миниатюра отображается отдельно от изображения скана и целиком показывает форму кривых в пределах области превью.
- **SC-003**: Оператор может векторизовать отдельное слово из списка и увидеть обновлённый статус и миниатюру после успеха менее чем за 3 действия (найти слово → нажать кнопку → увидеть результат).
- **SC-004**: В негативных сценариях векторизации (серверная ошибка / сеть) в 100% случаев оператор получает понятное сообщение, а ранее корректная миниатюра/статус не заменяются пустыми или ложными данными.
- **SC-005**: Не менее 90% участников ручной проверки однозначно понимают, что миниатюра — это форма штрихов слова, а не слой поверх скана.

## Assumptions

- Серверная векторизация и поле `curvePoints` уже доступны (фича `001-word-stroke-vector`): чтение слов скана возвращает `curvePoints` (`null` или массив кривых), а векторизация одного слова выполняется существующим запросом векторизации в контексте скана.
- Список слов показывается на существующем основном экране работы со сканом (отдельный маршрут/экран не требуется).
- Формат списка vs таблицы — на усмотрение реализации, при условии читаемости колонок «текст / статус / миниатюра / действие».
- Подписи статуса и кнопки — на русском языке, в духе текущего UX.
- Координаты `curvePoints` — в системе выровненного фрагмента слова (см. ADR/research фичи `001-word-stroke-vector`); клиент строит миниатюру только в этой системе.
- Повторная успешная векторизация заменяет представление; UI отражает одно актуальное превью на слово.
- Batch-векторизация, редактирование вектора и геометрически точное наложение на скан — сознательно вне scope и могут стать отдельными фичами.
