Inline-редактирование текста слова в блоке результатов OCR.

Контекст: оператор работает со сканом; распознанный текст показывается в текстовом блоке построчно, каждое слово кликабельно. Сейчас текст слова правится только в отдельной панели редактирования (поле «Текст» + кнопка «Сохранить»). Нужно добавить редактирование текста непосредственно в текстовом блоке.

Поведение:
- Первый клик по слову — выбор слова, как сейчас: подсветка в тексте, рамка на скане, открывается панель редактирования.
- Второй клик по уже выбранному слову — слово становится редактируемым inline (поле ввода на месте слова); курсор устанавливается в позицию, соответствующую месту клика.
- Завершение inline-редактирования по Enter или при потере фокуса (blur): если текст изменился — автоматически сохранить на сервер; если не изменился — просто выйти из режима редактирования.
- Escape — отменить несохранённые правки текста и вернуть последнее сохранённое значение; выйти из inline-режима без сохранения.

Регрессии (MUST NOT ломаться):
- Drag-and-drop порядка слов в recognized-text (drop на слово, на строку, межстрочные gap-зоны).
- Редактирование рамки слова на скане (перемещение и углы).
- Выбор слова кликом по рамке на скане.
- Добавление нового слова, распознавание, пакетная векторизация, удаление слова/скана.

Не входит в объём:
- Изменения backend, API и схемы БД.
- Редактирование нескольких слов одновременно.
- Автосохранение текста при правке в поле «Текст» панели редактирования (там остаётся явная кнопка «Сохранить»).
- Редактирование векторного представления (curvePoints).

Спецификация описывает **inline-редактирование текста слова** в блоке `recognized-text`:

| 1-й клик | Выбор слова (как сейчас): подсветка, рамка на скане, панель |
| 2-й клик по выбранному | Inline-поле на месте слова, курсор по позиции клика |

**Question:** Если автосохранение после inline-редактирования завершилось ошибкой, должен ли оператор оставаться в inline-режиме с возможностью повторить попытку или выходить из inline-режима с сохранённым в черновике текстом?

Это важно, потому что от выбора зависит, теряет ли оператор несохранённый текст и как именно выглядит восстановление после сбоя сети или сервера.

**Recommended:** Option A — оставаться в inline-режиме с введённым текстом и показать ошибку; оператор может исправить и повторить Enter/blur. Так меньше риск потери правок и поведение согласовано с явной кнопкой «Сохранить» в панели, где черновик сохраняется при ошибке.

**Question:** Что должна делать кнопка «Отмена» в панели редактирования, если в этот момент слово находится в inline-режиме?

Это важно, потому что «Отмена» и Escape могут по-разному отменять правки — только текст или весь черновик слова целиком.

**Recommended:** Option A — «Отмена» работает как сейчас: выход из inline-режима, закрытие панели, полный откат черновика (текст и координаты рамки) к последним сохранённым на сервере значениям. Это согласовано с текущим поведением кнопки и отличается от Escape, который отменяет только текст и оставляет панель открытой.

| Option | Description |
|--------|-------------|
| A | Полная отмена, как сейчас: выход из inline, закрытие панели, откат текста и координат к сохранённым на сервере |
| B | Как Escape: выход из inline, откат только текста; панель остаётся открытой с несохранёнными координатами |
| C | Сначала завершить inline по правилам blur (автосохранение при изменении текста), затем выполнить обычную «Отмену» |

**Question:** Как отличить второй клик по уже выбранному слову (вход в inline-режим) от начала перетаскивания этого же слова для смены порядка?

Это важно, потому что слова в текстовом блоке уже поддерживают drag-and-drop, и без явного правила второй клик может ошибочно запускать перетаскивание вместо inline-редактирования.

**Recommended:** Option A — если слово уже выбрано, короткий клик без заметного смещения курсора открывает inline-режим; перетаскивание начинается только после превышения порога перемещения. Так сохраняется и второй клик, и DnD порядка слов.

| Option | Description |
|--------|-------------|
| A | Порог перемещения: клик без смещения → inline; drag — только после движения мыши за порог |
| B | Drag отключён для выбранного слова, пока оператор явно не кликнет вне слова и снова не начнёт drag |
| C | Вход в inline только по двойному клику; одиночный второй клик не меняет режим |

- **Frontend-only** — backend/API без изменений.
- Новый state: `inlineEditingWordId`, `pendingWordGesture` (click vs drag, порог **5px**).

- При ошибке save — остаёмся в inline (FR-015).
- Файлы: `App.tsx`, опционально `inlineWordEdit.ts` / `InlineWordInput.tsx`, `App.css`.
