# Batch vectorization issue
_Exported on 8/14/2026 at 13:47:12 GMT+7 from Cursor (3.15.19)_

---

**User**

При batch векторизации, если сменить скан во время векторизации, отобразится текст и результат векторизации другого скана.

---

**Cursor**

Разбираюсь с багом: при смене скана во время batch-векторизации может показываться результат другого скана. Сначала изучу код векторизации и переключения сканов.


Похоже на race condition: при смене скана сбрасывается UI, но завершившийся batch может перезаписать состояние. Добавлю инструментацию для проверки гипотез.


Вы описали классическую **race condition**: при смене скана UI сбрасывается, но запрос пакетной векторизации продолжает выполняться и по завершении перезаписывает состояние нового скана.

**Гипотезы:**

1. **H-A**: Колбэк `vectorizeBatch().then()` безусловно вызывает `setWords(data)` с результатами **старого** скана, перезаписывая слова **нового**.
2. **H-B**: `handleScanRowClick` сбрасывает `isBatchVectorizing`, но **не отменяет** in-flight запрос — фоновый batch продолжает работать.
3. **H-C**: Гонка между `fetchWords` (новый скан) и завершением batch — побеждает тот, кто завершится последним.
4. **H-D**: `setDraft` ищет слово по `id` в результатах batch; при совпадении id между сканами черновик обновляется данными чужого скана.
5. **H-E**: После смены скана UI не показывает векторизацию, но batch всё ещё идёт и позже меняет текст/статус.

В код добавлена инструментация для проверки этих гипотез. Нужно воспроизвести баг.

4. Дождитесь завершения векторизации (статус «Пакетная векторизация завершена» или появление векторизованных слов).
5. Убедитесь, что отображаются текст и/или результаты векторизации **не того** скана.

**Cursor**

Логи подтверждают H-A и H-B: batch завершается с `willOverwrite: true` (стр. 26, 31–32, 52). Вношу исправление — инвалидация in-flight запросов при смене скана.


**Анализ логов (до исправления):**

| Гипотеза | Результат | Доказательство |
|----------|-----------|----------------|
| **H-A** — batch перезаписывает слова другого скана | **CONFIRMED** | Стр. 26: `requestScanId:45, currentScanId:41, willOverwrite:true`; стр. 52: `requestScanId:43, currentScanId:41` |
| **H-B** — запрос не отменяется при смене скана | **CONFIRMED** | Стр. 8: смена скана при `isBatchVectorizing:true`, batch завершился позже (стр. 26) |
| **H-C** — гонка fetchWords vs batch | **CONFIRMED** | Стр. 25 загрузил «Аскидия», стр. 26 batch перезаписал «5)» |
| **H-D** — draft по совпадающему id | INCONCLUSIVE | Логов draft не было |
| **H-E** — UI сбрасывает флаг, запрос жив | **CONFIRMED** | Стр. 8 + 26 |

**Исправление:** добавлен `editorGenerationRef` — при смене скана (`resetEditorState`) счётчик увеличивается, и все in-flight колбэки (batch, одиночная векторизация, загрузка слов) проверяют, что generation и `scanId` не изменились, прежде чем обновлять состояние.

Нужна проверка после исправления — в логах при смене скана во время batch должно быть `skipped: true`, а текст текущего скана не должен меняться.
