Таблица показывает как минимум: текст слова, id скана, статус векторизации, миниатюру вектора для векторизованных слов (существующий компонент WordCurveThumbnail). Клик по строке ведёт на существующий редактор скана с выбранным словом. Таблица должна поддерживать постраничную навигацию.

Так как сейчас нет способа получить слова сразу всех сканов одним запросом (только GET /api/Scans/{id}/words по одному скану), нужен новый read-only backend endpoint для получения слов кросс-сканово, с поддержкой серверной пагинации, поиска по тексту и фильтра по статусу векторизации/скану. Существующие endpoint'ы работы со словом (создание, обновление, удаление, векторизация одиночная и batch) не меняются.

Дополнительно: на той же странице добавить две отдельные кнопки экспорта датасета для последующего offline ML-пайплайна (кластеризация штрихов на буквы, затем обучение генеративной модели рукописных штрихов):
- «Экспортировать всё» — выгружает все векторизованные слова из всех сканов, независимо от текущих значений поиска и фильтров в таблице.
- «Экспортировать отфильтрованное» — выгружает только слова, попадающие под текущие активные поиск/фильтры таблицы (тот же набор, что оператор видит постранично на экране, но не только текущая страница — весь отфильтрованный набор целиком).

Обе кнопки формируют файл одинакового формата, различие только в наборе слов, попадающих в выгрузку. Если отфильтрованный набор пуст, кнопка «Экспортировать отфильтрованное» неактивна или явно сообщает, что нет слов для экспорта, без ошибки интерфейса.

Экспорт выполняется целиком на фронтенде: клиент загружает данные слов через endpoint(ы) чтения слов (постранично, пока не будут получены все нужные слова для выбранного вида экспорта), фильтрует только слова с непустым и валидным curvePoints, формирует файл в формате JSONL (одна строка — одно слово, аналогично isWordVectorized/filterValidCurves для критерия «векторизовано») и инициирует скачивание файла в браузере (Blob + ссылка на скачивание), без отправки данных куда-либо ещё.

Формат одной строки экспорта — JSON-объект с полями:
- wordId (число)
- scanId (число)
- text (строка, распознанный текст слова)
- curves — массив кривых слова как есть из curvePoints (массив кривых, каждая — 4 точки [x,y], в системе координат фрагмента слова), без разделения на штрихи, без сведений о порядке нанесения штрихов и без параметров векторизации (paddingPx, approximationTolerance) — эти данные не нужны и не включаются.

Экспорт должен:
- пропускать слова с пустым или невалидным curvePoints без ошибки всего экспорта
- сформировать один файл на каждый вид экспорта (например, words-dataset-all.jsonl и words-dataset-filtered.jsonl) и скачать его через браузер
- показать оператору количество экспортированных слов после завершения каждого экспорта и понятное текстовое сообщение об ошибке, если загрузка данных для экспорта не удалась
- не блокировать использование таблицы (поиск, фильтры, пагинацию) во время выполнения экспорта, либо явно блокировать только соответствующую кнопку экспорта на время его выполнения

Backend для этой фичи меняется минимально: только новый read-only endpoint(ы) для получения слов кросс-сканово с пагинацией/поиском/фильтрами, без изменений схемы БД, без изменений формата слова, без изменений существующих операций записи (создание/обновление/удаление/векторизация слова).

| Option | Description |
|--------|-------------|
| A | «Таблица слов» — отдельный полноэкранный режим; клик по строке заменяет его редактором скана; возврат — явной кнопкой «К таблице слов» |

**Question:** В каком порядке строки должны быть отсортированы в глобальной таблице слов по умолчанию?

Порядок сортировки задаёт стабильную пагинацию и то, как оператор видит слова при просмотре без явной сортировки — это напрямую влияет на SQL-запрос backend и приёмочные тесты.

**Recommended:** Option A — сначала `scanId` по возрастанию, затем `orderIndex` внутри скана. Это сохраняет порядок чтения внутри каждого скана и даёт предсказуемую группировку по документам.

| Option | Description |
|--------|-------------|
| A | `scanId` по возрастанию, затем `orderIndex` внутри скана (порядок чтения) |

| C | Текст слова по алфавиту (без учёта регистра) |
| D | `scanId` по убыванию (новые сканы первыми), затем `orderIndex` |
