Редактирование координат рамки слова на изображении скана через drag-and-drop.

Контекст: в редакторе скана слова отображаются рамками поверх изображения. Сейчас координаты четырёх вершин рамки (x1–y4) можно править только числовыми полями в панели редактора; изменения видны в черновике до нажатия «Сохранить». Нужно добавить интерактивное редактирование рамки непосредственно на скане.

Целевые действия:
1. Перемещение всей рамки — оператор перетаскивает выбранную рамку, все четыре вершины сдвигаются на одинаковое смещение.
2. Изменение формы рамки — оператор перетаскивает отдельные углы рамки; каждый угол двигается независимо (рамка может наклоняться и менять размер).

UX и поведение:
- Редактирование drag-and-drop доступно только для выбранного слова (черновик). Клик по рамке на скане или по слову в тексте выбирает слово, как сейчас.
- У выбранной рамки должны быть видимые маркеры (ручки) на четырёх углах.
- Во время перетаскивания рамка и числовые поля x1–y4 в панели редактора обновляются синхронно (live preview).
- Сохранение на сервер — только по существующей кнопке «Сохранить» (текст и координаты); автосохранения при отпускании мыши нет.
- «Отмена» возвращает координаты к последним сохранённым данным, как для числового редактирования.
- Для нового несохранённого слова (без id) оператор может задать начальную рамку перетаскиванием углов на скане, затем сохранить слово обычной кнопкой.
- Сообщения и статусы — на русском, в стиле существующего редактора («Сохранение», «Сохранено», ошибки сохранения).

Ограничения и регрессия:
- Backend, схема БД и API не меняются; используется существующее сохранение слова (текст + координаты).
- Drag-and-drop порядка слов в текстовом блоке recognized-text (включая gap-зоны для новых строк) MUST работать без регрессии.
- Числовое редактирование координат в панели MUST оставаться рабочим и синхронизированным с рамкой на скане.
- Сохранение порядка слов («Сохранить порядок») не затрагивается; изменение координат не меняет lineIndex/orderIndex.

Out of scope:
- Автосохранение координат при отпускании мыши.
- Изменения серверного API, отдельный endpoint «только координаты».
- Drag-and-drop слов между рамками на скане (перестановка порядка — только в текстовом блоке).
- Touch/клавиатурное редактирование рамок, мультивыбор нескольких рамок.
- Автоматическая пересчётка или сброс curvePoints/векторизации после сдвига рамки (повторная векторизация — по желанию оператора, как сейчас).
- Ограничение рамки границами изображения (если не оговорено иначе — оператор может вывести вершины за край и поправить вручную).

Критерии успеха (ожидания):
- Оператор может скорректировать положение рамки на скане без ввода чисел в поля x1–y4.
- После «Сохранить» координаты совпадают с тем, что было видно на скане до сохранения; после перезагрузки скана рамка на том же месте.
- Существующие сценарии: выбор слова, сохранение/отмена, DnD порядка в тексте, добавление нового слова — без регрессии.

**Question:** За какую часть выбранной рамки оператор должен тянуть, чтобы переместить её целиком, а не отдельный угол?

Это определяет зоны захвата и приоритет угловых маркеров — без этого нельзя однозначно написать FR-001 и сценарии приёмки.

**Recommended:** Option A — внутренняя область четырёхугольника, угловые маркеры имеют приоритет при попадании курсора в их зону. Это стандарт для редакторов разметки, совпадает с формулировкой «область рамки (не угол)» и естественно разделяет перемещение и правку формы.

| Option | Description |
|--------|-------------|
| A | Внутренняя заливка рамки (полигон минус зоны угловых маркеров); углы имеют приоритет |
| B | Только рёбра рамки (линии между углами), не углы и не центр |
| C | Отдельная «ручка перемещения» в центре рамки |
| D | Любая точка рамки, кроме угловых маркеров (включая рёбра и центр) |
| Short | Свой короткий ответ (≤5 слов) |

Можно ответить буквой (например, «A»), принять рекомендацию («yes» / «recommended») или дать свой короткий ответ.

**Question:** Если оператор нажимает на рамку **ещё не выбранного** слова и, не отпуская кнопку, тянет мышь — что должно произойти?

Это задаёт модель «выбор → правка» и влияет на FR-003 и сценарии приёмки.

**Recommended:** Option C — при нажатии на невыбранную рамку слово только выбирается; перемещение или правка углов начинаются только если слово **уже было выбрано** в момент нажатия. Так не будет случайного сдвига координат при выборе, в том числе у перекрывающихся рамок.

| Option | Description |
|--------|-------------|
| A | Два явных шага: сначала клик (отпустить кнопку), затем отдельное перетаскивание |
| B | Один жест: нажатие + перетаскивание на невыбранной рамке сразу выбирает слово и двигает рамку |
| C | Нажатие на невыбранной рамке только выбирает; drag координат — только если слово уже выбрано при нажатии |
| D | Нажатие на невыбранной рамке выбирает; drag в том же жесте двигает рамку только после порога смещения (например, >5 px) |
| Short | Свой короткий ответ (≤5 слов) |

Можно ответить буквой, принять рекомендацию («yes» / «recommended») или дать свой короткий ответ.

**Question:** Если рамки двух слов перекрываются и оператор кликает в общую область — какое слово должно выбираться?

**Recommended:** Option A — слово с рамкой, нарисованной поверх остальных (верхний слой). Это стандартное поведение наложенных элементов: выбирается то, что оператор видит сверху.

| C | Слово с меньшим orderIndex (раньше в порядке чтения) |
| D | Уже выбранное слово, если курсор в его рамке; иначе верхний z-order |
